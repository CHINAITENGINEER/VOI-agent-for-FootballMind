## A. 文本语义表示与 Embedding

### 通俗解释

神经网络读不懂英文句子。Embedding 就是**把一段话压成一串固定长度的数字**，让"意思相近的段落，数字也相近"。就像给每篇文章一个坐标，意思接近的文章坐标就接近。

### 数学定义

编码器 `E` 把可变长度的文本 `t` 映射为固定维度向量：

```
E : t → v ∈ R^d,   ‖v‖₂ = 1
```

本项目采用 Matryoshka 前缀截取：`v₂₅₆ = L2(v₁₀₂₄[0:256])`。

### 输入与输出

| 项 | 内容 |
|---|---|
| 输入 | 正文**全文**（`verbatim_no_prompt_no_title_injection_no_truncation`） |
| 池化 | `last_nonpadding_token` |
| 原生产出 | **1024** 维，L2 归一化 |
| 项目使用 | 取前 **256** 维后再 L2 归一化 |
| 编码器 | `Qwen/Qwen3-Embedding-0.6B`，revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，595,776,512 个冻结参数 |
| token 上限 | 短契约 8192 / 长契约 32768；**同一冻结权重、池化与 dtype**，只有显式 token 界限与契约标识不同 |

### 项目位置

- **f 的输入**：每篇已采用正文的 256 维向量（作为集合元素，或用 GRU 按序列读入）。
- **g 的输入**：候选正文 256 维（`candidate_embedding`）+ 已采用正文均值 256 维（`adopted_mean_embedding`）+ 二者的绝对差 256 维 + 逐元素积 256 维。

### 为什么选它

1. **样本量限制**：正文监督量只有 **294 场 / 521 篇**。在这个规模上从零训练文本表示不可能。
2. **冻结即承认约束**：不微调编码器，用预训练先验代替数据。
3. **可复现性**：向量预编码并缓存（`gpu-import-v1\embeddings.npz`），运行时不现场编码，保证演示可复算。

### 与其他模块的关系

```
正文全文 ──► 冻结编码器 ──► 1024 维 ──► 取前 256 维 + L2 ──┬─► f（已采用集合）
                                                        └─► g（候选 + 已采用均值 + 差 + 积）
```

### 代码入口与训练过程

- 编码计划：`E:\FootballMind\experiments\full-history-sequential-fg-20261025-v1\semantic-initial\encoding-plan.json`
- 编码器来源与契约：`f-fit-vectors\encoder-provenance.json`
- 向量包：`gpu-import-v1\embeddings.npz`（来源计数：既有本地 CPU 缓存 1,712 + 冻结交接 CPU 对照 8 + 验证通过的 GPU 结果 1,286）
- **推理过程中编码器不参与训练**；本轮训练的参数量不含编码器。

### 已有实验结果

- 8 个 CPU 对照通过，最小余弦 **0.9999999999940907**，最大逐元素差 **4.2468e-07**。
- 最长正文（15,446 token）已完整编码，**未截断**、未分段平均；峰值显存 allocated 3.04 GiB。
- 一笔如实记录的限制：**那 8 个 CPU 对照里不包含最长的这一篇**；其完整性由原文 SHA、token 数与执行记录支持。

### 适用范围与限制（必须同时讲）

1. **语义相似度 ≠ 预测价值**。向量能说"两段话在讲同一类事"，不能说"这篇会不会改变胜负概率"。
2. **对语料外球队存在 OOV 问题**。早期项目（C 集）实测：项目自训 TF-IDF 词表对语料外球队查询的 OOV 率达 **30.8%–58.3%**，在真实 Inter 菜单上 AP 掉到 **0.071**（预训练模型 0.55–0.68）。**新版已改用预训练编码器，OOV 问题在原理上缓解，但新版本没有重做这个对照实验。**

### 评委可能问什么

| 追问 | 回答要点 |
|---|---|
| 为什么不全用 1024 维？ | 256 维是 Matryoshka 前缀截取，匹配监督量。**如实说：没有做过 1024 vs 256 的头对头对照** |
| 为什么不微调？ | 样本量 + 来源捷径风险。早期已量化该风险：把标题替换成常数，测试误差反而下降 |
| 编码器会不会看过测试集？ | 不会。编码器只做前向，无监督信号；且**正文发布时间严格早于比赛日（3,001/3,001）** |

### 可直接使用的解释句

> 我们没有自己训练文本表示，而是用一个冻结的开源编码器把正文变成 256 维向量。这样做是因为正文监督量只有 294 场、521 篇——在这个规模上微调大模型，最大的风险是把"这篇文章来自哪个网站"当成捷径学进去，而不是学会判断内容价值。

## B. 预测器 f

### 通俗解释

f 就是那个"给概率的东西"。你告诉它"我已经读了这几篇报道"，它告诉你"主胜多少、平局多少、客胜多少"。

### 数学定义

```
f_θ : ( S , M , p_s0 ) → p ∈ Δ²
```

其中 `S` 为已采用正文集合（每篇 256 维向量），`M` 为元数据，`p_s0` 为初始先验，`Δ²` 是三维概率单纯形。

集合版本采用**置换不变**结构：`f(S) = f(π(S))` 对任意置换 `π` 成立（已在实验中验证最终 L1 = 0）。

### 输入与输出

| 项 | 内容 |
|---|---|
| 输入 | 已采用正文的 256 维向量集合 + **16 维生效元数据** + s0 先验 |
| 元数据明细 | `log1p_days_before_match`、`publication_time_unknown`、`historical_version_unknown`、`source_is_official`、`log1p_body_characters`、`historical_reconstruction`、`candidate_claims_unknown`、`factual_update_unknown`、`source_official_unknown`、`exact_home_team_mentions`、`exact_away_team_mentions`、`target_aliases_unknown`、`target_aliases_partial`、`source_target_home`、`source_target_away`、`source_target_unknown` |
| 输出 | `(p_home, p_draw, p_away)`，和为 1 |
| 概率顺序 | `["home", "draw", "away"]` |

### 项目位置

运行时闭环的**第 ⑦ 步**。它是唯一输出最终概率的模块。

### 为什么这样设计

1. **残差式**：初始残差头为 0，所以 epoch 0 的输出**恰好等于冻结的校准先验**。模型学的不是"从零预测"，而是"文本带来的修正量"。这在小样本上更稳。
2. **s0 有明确语义**：`s0 = "calibrated market prior; no text residual"`，即**空证据状态就是校准后的市场先验**。

### 与其他模块的关系

```
s0 先验 ──┐
已采用向量 ─┼─► f ──► 概率 ──┬─► 计算 L_before / L_after（标签生成）
元数据 ────┘                  └─► 作为 g 的状态输入（概率 3 维 + 隐状态 64 维）
```

### 代码入口

- 模型定义：`football_research\acquisition\sequential_evidence_f.py`
- 元数据构造：`football_research\acquisition\full_history_sequence_metadata.py`
- 训练脚本：`tools\train_full_history_sequence_f.py`
- 冻结配置：`models\f\model.json`

### 训练过程（逐步）

1. 用 **f_train 294 场 / 521 篇**构造训练样本。
2. 损失 = 交叉熵，**先对每场的全部前缀平均（含 s0），再对所有比赛等权**。
3. 优化器 AdamW：lr **0.001**，weight_decay **0.01**，betas **[0.9, 0.999]**，eps **1e-8**，grad clip **5.0**；batch = **32 场比赛**；最多 **200 epoch**；早停 patience **25**，最小改善 1e-7。
3 seed：11 / 29 / 47。
4. 用 **f_dev 74 场**按 `match_balanced_prefix_log_loss` 选检查点（**导出前恢复检查点**）。
5. 冻结：`parameter_updates_during_predict = false`；基础校准器在正文训练阶段已冻结。
6. 保存 SHA 与源文件哈希（见 `model.json` 的 `source_hashes`）。

### 已有实验结果

| 模型 | f_dev log loss | test log loss |
|---|---:|---:|
| 原始市场先验 | 0.965245 | **1.020413** |
| 校准先验（= s0） | 0.963980 | 1.022476 |
| 集合 f（选中） | 0.962041 | 1.022482 |
| GRU f（选中） | **0.958916** | 1.026598 |
| **场数** | 193 | 320 |

**必须同时说的三句**：
- **f_dev 上新 f 有改善**（集合 0.962041 < 校准先验 0.963980 < 原始市场 0.965245）。
- **test 上原始市场先验最好（1.020413）**，新 f 未在这个主测试集合上证明优于它。
- 集合 f 与校准先验几乎相同（1.022482 vs 1.022476），**不能解释成明确提升**。

### 适用范围与限制

1. `best_epoch = 1`（集合与 GRU 都是）——**继续训练不能改善 f_dev**。
2. 旧 f 只在"有相同正文/claim 的共同子集"上比较（validation 19 场、test 6 场），**样本极小，不能做大结论**。
3. 正文训练量 294 场，**不能说"在 24,911 场正文上训练"**。

### 评委可能问什么

| 追问 | 回答要点 |
|---|---|
| 为什么 best_epoch 是 1？ | 如实答：在 f_dev 上选出的检查点是第 1 个 epoch，说明当前监督信号下继续训练不能改善开发集损失 |
| 为什么 s0 不等于市场报价？ | s0 是**校准后**的先验，中间隔了 4 参数的基础校准器。市场报价 14.24/19.79/65.97，s0 是 12.95/19.39/67.65 |
| 训练时用了赛果吗？ | 用了。赛果是**训练标签**。但 `label_usage` 明确限定为 training and evaluation only，且 `parameter_updates_during_predict = false` |
| GRU 比集合好吗？ | 分集合看：f_dev 上 GRU 好，test 上集合好。**不能宣称 GRU 更优** |

### 可直接使用的解释句

> f 是一个残差结构的预测器：它的起点是校准后的市场先验，然后根据已经采用的正文来修正这个先验。我们用 294 场比赛来训练它，并且保证同一场比赛的多个证据前缀先平均、再按比赛等权，避免报道多的比赛被过度加权。

## C. 信息价值估计器 g（**最重要的一节**）

### 通俗解释

g 是那个"判断这篇值不值得读"的东西。你给它"我现在知道什么"和"这一篇讲了什么"，它给出一个分数，回答"读这一篇大概能让我的判断变好多少"。

### 数学定义

g 是对条件预测增益的条件期望的估计：

```
g_φ(s, a) ≈ E[ Δ_f | s, a ]
Δ_f = L_before − L_after
```

**它估的是关于某个固定 f 的经验有符号风险改善，不是精确 Bayes EVSI，不是长期 Bellman Q，也不是经济收益。**

### 输入与输出

- **输入**：1140 维（13 个块的完整分块表见 [08](08-data-dictionary-and-version-map.md) §3.2）
- **输出**：一个标量分数

**明确的禁止输入**（写在 schema 里）：`outcome`、`realized_gain`、`candidate_after_probability`、`candidate_after_hidden_state`。

### 项目位置

运行时闭环的**第 ④ 步**。它的输出交给**第 ⑤ 步的选择策略**。

### 为什么需要一个单独的 g

因为 f 只会算概率，不会判断"哪一篇值得读"。没有 g 就只有两个选择：全读（成本高、可能引入负增益）或按固定顺序读（与内容无关）。

### 为什么候选价值取决于已有证据

这是设计核心。g 的输入里专门给了三组关系量：

| 量 | 回答的问题 |
|---|---|
| `adopted_mean_embedding` | 我已经读了些什么？ |
| `absolute_difference` | 这一篇和已读的差多远？ |
| `elementwise_product` | 这一篇和已读的在哪些维度上重合？ |

所以 g 能表达"**这篇是补充，还是重复**"。

### 与其他模块的关系

```
当前状态（349 维，含 f 的概率、熵、计数、预算、已采用均值、f 隐状态）
        +
候选全文（256 维）+ 绝对差（256）+ 逐元素积（256）
        +
候选元数据（22）+ 最大相似度（1）
        = 1140 维 ──► g ──► 标量分数 ──► 选择策略（阈值 + 预算）
```

### 代码入口

- 定义：`football_research\acquisition\sequential_postread_g.py`
- 冻结配置与特征顺序：`models\g\model.json`、`models\g\feature-schema.json`
- 权重：`models\g\g-models.joblib`（SHA `5af947711279765838adb02e7dc09c2a9525a89e90db3e23e4f68a865ed88eff`）

### 训练过程

1. 选定**对应版本**的冻结 f。
2. 在 g_fit/g_dev 的历史状态上，计算每篇候选的 Δ_f 作为标签。
3. 训练 7 个头（zero / train_mean / state_ridge / fulltext_ridge / local_metadata_refit_ridge / fulltext_mlp × 3 seed）。
4. **标准化器只在训练折拟合**（`train_only_standardization = true`）。
5. 阈值候选 `[-0.01, -0.003, 0, 0.003, 0.01]`，**由 g_dev 的完整策略损失选定**，不按回归误差。
   - 集合 f 配套：选中 `state_ridge`，阈值 **0.0**
   - GRU f 配套：选中 `local_metadata_refit_ridge`，阈值 **0.01**
6. 训练规模：**479 场 / 7,600 转移拟合；160 场 / 2,846 转移开发**。（注意：10,446 转移不是 10,446 场比赛。）

### 已有实验结果（必须完整呈现，不能只挑好的）

**标签分布**（集合 f 侧）：正 **5,904** / 零 **0** / 负 **4,542**。
> 零计数为 0 是**有效标签的实际结果**，代码未筛除零或负收益。

**回归指标（比赛等权 macro MSE，越低越好）**：

| 头 | g_fit（479 场） | g_dev（160 场） | test（320 场） |
|---|---:|---:|---:|
| 恒零基线 | 0.00020807 | **0.00018271** | **0.00021162** |
| state_ridge | 0.00020628 | 0.00018614 | — |
| fulltext_mlp_seed20261027 | **0.0000067** | 0.00021990 | 0.00025242 |

**同一个表的两种读法都要会**：
- 读法一（拟合能力）：`fulltext_mlp` 在 g_fit 上 macro MSE 只有 **0.0000067**，**拟合极好**。
- 读法二（泛化能力）：同一个模型在 g_dev 上 **0.00021990**，在 test 上 **0.00025242**，**都差于恒零基线（0.00018271 / 0.00021162）**。

**这就是"训练—评估落差"的直接证据。**

**排序能力**：

| 头 | g_fit Spearman | g_dev Spearman | 说明 |
|---|---:|---:|---|
| state_ridge | 0.2213 | **0.0096** | 开发集上排序能力消失 |
| 正类符号准确率（state_ridge） | 0.6266 | 0.5130 | 开发集接近随机 |

**一个结构性的、必须讲清的事实**：

`state_ridge` 的输入**不含候选向量**，所以它在**同一状态下给所有候选相同分数**。冻结包明确记载：**"在 334 个多候选决策状态中全部候选同分，按冻结来源顺序破平；不是全文排序模型。"**

**所以 state_ridge 实际学的是"继续还是停止"，不是"选哪一篇"。** 而它却是开发集选定的策略。

### 适用范围与限制

1. **不得**说"g 会排序候选"——当选中的头是 state_ridge。
2. **不得**说"所有信息价值估计方法都无效"——只测了 7 个头、1 个标签定义、1 个数据规模。
3. `fulltext_ridge` 和三个 `fulltext_mlp` **能**排序，但**未证明在完整策略上优于随机**（见第 9 页实验）。
4. 所有头都**未做概率校准**（无 ECE、无可靠性图）。
5. g 的分数**不是经济收益**。

### 评委可能问什么

| 追问 | 回答要点 |
|---|---|
| g 究竟预测什么？ | 估计「在当前状态下采用这一篇候选，同一个冻结 f 的预测损失能改善多少」的条件期望 |
| 为什么同一篇正文在不同状态下价值不同？ | 因为 Δ_f 取决于当前已有证据；已有越多，边际贡献越小 |
| 既然 state_ridge 不会排序，为什么选它？ | 因为它**不是按排序能力选的，而是按 g_dev 完整策略损失选的**。它的作用是在合适时机停止 |
| 那你们有没有会排序的 g？ | 有。fulltext_ridge 和三个 fulltext_mlp 都能排序，但未证明在完整策略上优于随机 |
| 为什么参数更多反而更差？ | 直接证据：MLP 在 g_fit 上误差 6.7e-6，在 test 上 2.52e-4，而恒零基线是 2.12e-4。这是训练—评估落差，不是容量不足 |

### 可直接使用的解释句

> g 学的是一个非常具体的目标：**在当前这个状态下采用这一篇候选，同一个冻结预测器的预测损失会改善多少。** 它不是"文章好不好"的判断器，也不是赚钱模型。我们保留了 4,542 条负收益样本，因为"读一篇新闻反而变差"是真实存在的。

## D. Ridge 回归与 MLP

### 通俗解释

**Ridge** 是"带刹车的线性回归"：在小样本高维数据上，普通最小二乘会把噪声也学进去，加一个惩罚项就能压住。**MLP** 是"会拐弯的线性模型堆叠"，能表达更复杂的组合关系，但需要更多数据才不容易学偏。

### 数学定义

**Ridge**：

```
min_w  ‖Xw − y‖² + α‖w‖²
```

- `α‖w‖²` 是正则化项；`α` 越大，权重被压得越紧。
- 本项目所有 Ridge 头统一 `α = 10.0`。

**MLP**（本项目）：

```
R^1140 → Linear(1140,128) → ReLU → Linear(128,64) → ReLU → Linear(64,1)
参数总量 = 154,369
```

### 输入与输出

| 模型 | 输入 | 输出 | 参数 |
|---|---|---|---|
| `state_ridge` | 349 维状态 | 标量 | 350 |
| `fulltext_ridge` | 1140 维 | 标量 | 1141 |
| `local_metadata_refit_ridge` | 51 维元数据 | 标量 | 52 |
| `fulltext_mlp` | 1140 维 | 标量 | 154,369 |

### 项目位置

全部在 **g** 这一侧。**f 用的是残差 MLP 与 GRU，不是 Ridge。**

### 为什么低维结构化特征适合 Ridge

349 维状态在百量级比赛上，线性模型方差低、可解释、不易过拟合。事实支持这一点：`state_ridge` 在 g_fit 上的 macro MSE（0.00020628）**优于恒零基线（0.00020807）**。

### 为什么全文语义可能需要非线性

"候选与已采用证据是互补还是重复"是乘性关系。线性模型需要显式给出交互项（项目已给 `elementwise_product`），非线性层可以学更复杂的组合。

### 为什么参数量多 ≠ 更强（本项目有直接证据）

| | g_fit | g_dev | test |
|---|---:|---:|---:|
| fulltext_mlp_seed20261027 | **0.0000067** | 0.00021990 | 0.00025242 |
| 恒零基线 | 0.00020807 | **0.00018271** | **0.00021162** |

**MLP 的 test 误差大于恒零基线。** 报告原话："两套全文 MLP 都能显著拟合训练标签，但开发/测试没有胜过零基线。**这是训练—评估落差的直接证据；不能凭参数少认定容量不足。**"

### 三个 Ridge 必须分清（高频混淆点）

| 名称 | 位置 | 输入 | 作用 |
|---|---|---|---|
| **state_ridge** | 新版 g 的头，且是**开发集选定策略** | 349 维状态 | 决定继续/停止（同状态候选同分） |
| **fulltext_ridge** | 新版 g 的头 | 1140 维 | 线性候选排序 |
| 早期诊断 Ridge | C 集（51 场）embedding 基准 | 各种文本臂 | **历史诊断，不是运行模型** |

### 适用范围与限制

- 小样本下复杂模型可能仍不如简单基线——这是**本项目已实测到的结论**，不是理论担忧。
- MLP 的 epoch 由 **g_dev 比赛等权 MSE** 选择；最终模型与阈值由 **g_dev 完整预算 3 策略损失**选择。

### 可直接使用的解释句

> 我们用 Ridge 处理低维结构化状态，用 MLP 处理 1140 维的全文输入。但一个重要发现是：MLP 在训练集上拟合得极好——macro MSE 只有 6.7 乘以十的负六次方——在测试集上却是 2.52 乘以十的负四次方，**比恒零基线还差**。这说明问题不在模型容量，而在监督信号没有迁移到测试集。

## E. GRU 与序列状态

### 通俗解释

集合模型把"读过的文章"当成一袋东西，不管先后。GRU 是"带头记忆"的模型：它按顺序一篇篇读，用一个 64 维的隐状态记住"到目前为止读到了什么"。

### 数学定义

```
h_t = GRU(x_t, h_{t-1}),   h_0 = 0
p_t = softmax(W_o h_t + b_o)
```

`h_t ∈ R^64` 是第 t 篇读完后累积的记忆。

### 输入与输出

输入同 f（256 维正文 + 元数据 + s0 先验），但**按顺序逐步输入**；输出同 f（三分类概率）。

### 项目位置

f 的两种实现之一（对位的是集合残差 MLP）。

### 为什么同一场比赛有多个证据前缀

因为系统是序贯的：s0（未采用）→ s1（采用 1 篇）→ s2（采用 2 篇）。项目为每个候选都生成了 s0 转移，并有 3 个有界前缀顺序（源顺序 / 随机），**深度最多 3**。

### 当前实验是否证明 GRU 更好

**没有。** 证据是双向的：

| 指标 | 集合 f | GRU f | 谁更好 |
|---|---:|---:|---|
| f_dev log loss（193 场） | 0.962041 | **0.958916** | GRU |
| test log loss（320 场） | **1.022482** | 1.026598 | 集合 |

**顺序敏感性实测**：完整池 513 场 / 1,041 篇，源顺序 + 5 固定随机排列 → **集合 f 最终 L1 = 0**（置换不变，符合设计）；GRU 在多文 324 场上最大 L1 均值 ≈ 0.001374，最大 0.0122995，**无最高概率类别变化**。

### 适用范围与限制

1. **不能仅凭结构复杂就宣称更好**——本项目已实测到反向证据。
2. 报告明确说明：集合与 GRU 的**元数据使用存在差异**，所以比较结果**不能纯归因于循环结构本身**。

### 可直接使用的解释句

> 我们同时训练了集合式预测器和 GRU 序列预测器。结果是分集合的：开发集上 GRU 更好，测试集上集合模型更好。所以我们**不声称 GRU 更优**——而且两者的元数据使用有差异，这个比较本身不够干净。

## F. 条件预测增益与标签生成

### 通俗解释

要给 g 一个"标准答案"，就得知道"读这一篇到底让预测变好了多少"。做法是：**让同一个预测器先做一次预测，再让它读了这篇之后再预测一次，两次的损失差就是标准答案。**

### 数学定义

```
Δ_f = L_before − L_after

当 L = −log p_f(Y) 时：
Δ_f = log p_after(Y) − log p_before(Y)
```

### 逐项解释（每个符号都要能解释）

| 符号 | 含义 | 本项目中的具体所指 |
|---|---|---|
| `f` | 冻结预测器 | `set_residual_mlp-seed47` 或 GRU；SHA `b36b2cf8…` |
| `Y` | 历史赛果 | 主胜 / 平局 / 客胜；只在训练与结算使用 |
| `L_before` | 采用前损失 | `−log p_f(Y)`，作用于当前状态前缀 |
| `L_after` | 采用后损失 | 把候选向量加入已采用集合后重算 |
| `Δ_f` | 增益 | 正 = 改善；零 = 无变化；负 = 变差 |

### 三类标签各代表什么

| 符号 | 含义 | 实际数量（集合 f 侧） |
|---|---|---:|
| 正 | 采用后评分改善 | **5,904** |
| 零 | 无变化 | **0** |
| 负 | 采用后评分变差 | **4,542** |

**为什么同一篇正文在不同状态下 Δ_f 不同**：因为 `L_before` 是状态的函数。已有证据越多，边际贡献越小；与已有证据重复时，Δ_f 接近或等于零。

### 为什么这**不是**通用的经济收益

| 维度 | Δ_f | 经济收益 |
|---|---|---|
| 单位 | log loss 的差（无量纲评分单位） | 货币 |
| 是否含成本 | 不含 | 含 |
| 是否含市场价 | 不含 | 含（赔率） |
| 是否含风险约束 | 不含 | 应含 |

**所以**：Δ_f 是**经验预测增益的监督定义**，不是已经证明的因果效应，也不等于实际收益。

### 版本约束（必须讲）

- Δ_f **依赖具体的 f**。换 f 就换标签。
- 旧版 g 的状态在模型资产表里记录为 `not_reused_across_incompatible_f_binding`——**不能跨 f 版本复用 g**。
- 旧版与新版**使用不同标签定义**，**不能合并成一个统一流程**。

### 可直接使用的解释句

> 我们的标签是这样算的：**冻结同一个预测器，让它先基于当前已知信息预测一次，再让它读了这篇候选正文之后重新预测一次，两次预测损失的差值就是这篇正文在这一状态下的价值。** 这个标签依赖具体哪个预测器，所以换预测器必须重新生成标签，不能复用。

## G. 证据准入与未知状态处理

> ⚠️ **版本提醒**：本节机制属于**旧版在线原型**（`football_agent\directional_evidence.py`）。**新版全文序列研究使用的是连续增益标签 Δ_f，没有接入这套四项门控。**

### 通俗解释

新闻说"某球员正在康复训练"。这句话**既不是"会出场"，也不是"会缺阵"**。如果系统直接把它当成方向性证据，就会错误地改变概率。四项准入就是**四道安检**。

### 四项条件

| 条件 | 要求 | 举例 |
|---|---|---|
| **方向标签** | 明确表达利好或利空 | "缺阵" = 利空 |
| **相关主体** | 明确指向哪名球员/哪支球队 | "Brentford 的 A 球员" |
| **方向依据** | 说明方向的理由 | "因伤" |
| **原文引文** | 逐字引文 | 直接从正文摘取 |

**四项同时成立才允许影响后验。**

### 三种状态的准确含义

| 状态 | 含义 | 对概率的作用 |
|---|---|---|
| `supports` / `refutes` | 四项齐全 | 允许进入联合模型 |
| `no_answer` | 正文存在但不足以支撑该场次的具体断言 | **不改变后验** |
| `unknown + availability_only` | 只有状态、没有方向 | **不改变后验** |

### 为什么"正在康复" ≠ "确定缺阵"

因为"正在康复"只描述**当前的身体状态**，没有说明**对本场比赛的影响方向**。它可能是利空（不能出场），也可能是利好（恢复顺利）。**在方向未确定时更新概率，就是用未验证的假设污染后验。**

### 为什么"证据不足时不更新"更合理

因为错误更新的代价不可逆。项目在真实历史面板上的观察：**5 条观察中只有 1 条通过四项检验，4 条被判 `no_answer`**。

### 规则式准入 vs 学习式分类器

| | 规则式（本项目） | 学习式 |
|---|---|---|
| 定义方式 | 人工定义契约 | 从数据学 |
| 优点 | 可审计、可逐条检查 | 可能发现人没想到的模式 |
| 缺点 | 可能误排有效信息 | 需要标注、难审计 |

**真实失败案例**：一篇苏格兰队的相关正文，因未通过五主题词表提取而被排除。

### 已有真实运行证据

- 面板 5 条观察 → 1 条 `supports + match_specific`，4 条 `no_answer`。
- 唯一通过的那条使后验从 **53.49% / 30.23% / 16.28% → 50.73% / 31.04% / 18.23%**。
- **这证明了代码路径真实运行，不证明门控有效。**

### 适用范围与限制（必须主动说）

1. **从未做过门控消融**——不知道去掉任一条件后错误更新率会怎么变。
2. 面板只有 **5 条观察**，做 5 臂消融等于每臂 1 条，**没有统计意义**，所以该消融目前不可行。
3. 方向判断本身来自**冻结的语义模型**，**未经校准**。
4. 概率变化幅度 ≤ 2.8 个百分点，可能是噪声。
5. **不得**称为"已验证的完美事实核查系统"。当前是**待验证的设计贡献**。

### 可直接使用的解释句

> 我们设了一道保守的证据准入：**一条正文只有在方向、主体、方向依据和逐字引文四项同时成立时，才被允许影响概率。** 像"正在康复训练"这种只有状态、没有方向的句子，我们把它标记为未知，不改概率。但我要说明：**这套门控我们从未做过消融，因为真实面板上只有 5 条观察，做消融没有统计意义。**

## H. 选择策略与停止

### 通俗解释

g 给了分数，但"多少分才值得读"还需要一个规则。选择策略就是这条规则：**分数超过阈值且预算没花完，就读；否则停。**

### 五个策略的准确定义

| 策略 | 定义 | 是否使用内容信息 |
|---|---|---|
| **不采用正文** | 只用 s0 | ✗ |
| **固定顺序** | 按冻结的候选顺序逐篇采用 | ✗（与内容无关） |
| **随机采用** | 随机选篇；每场 10 个 seed 先平均，再按比赛等权 | ✗ |
| **基于 g 的选择** | 用 g 的分数 + 阈值 + 预算 | ✓ |
| **全部采用（all）** | 完整池无上限参照 | ✗ |

> **注意**：`all` 是**无上限参照**，**不能声称它与预算 3 的成本相同**。

### 阈值是怎么定的

阈值候选 `[-0.01, -0.003, 0, 0.003, 0.01]`，**由 g_dev 上的完整策略损失选定**，不按回归误差选。集合 f 配套选中 `state_ridge` + 阈值 **0.0**。

### 停止条件

1. 所有候选分数低于阈值 → 停止（本例的 `stop_reason = predicted_gain_below_frozen_threshold`）。
2. 预算耗尽 → 停止。

**⚠️ 当前停止规则没有全局最优性的理论保证。** 它是在声明范围内的工程停止规则。

### 为什么必须同池同预算比较

否则差异可能来自"候选池不同"或"读得更多"，而不是来自选择策略本身。

### 单步与两步前瞻（早期研究，注意版本）

早期项目做过"两步前瞻"研究：目录页本身不改概率，但可能引出有用正文。**这属于旧版研究与 C 集诊断，不是新版主线的机制。** 新版主线的策略是阈值 + 预算规则。

### 可直接使用的解释句

> 我们比较了五种策略，关键是**同池、同预测器、同预算**。停止规则很简单：所有候选分数低于阈值就停，或预算花完就停。**我要明确说，这个停止规则没有全局最优性的理论保证**——它是一个工程规则，不是最优停止算法。

## I. 实验评估算法

### 通俗解释与定义

| 指标/方法 | 通俗解释 | 定义 | 本项目用在哪 |
|---|---|---|---|
| **Log Loss** | "给真实结果的概率越低，罚得越重" | `−log p(真实结果)` 的平均 | **主指标**：策略比较、f 评估 |
| **Brier Score** | "预测概率与真实 0/1 的平方距离" | `Σ(p_i − y_i)²` 的平均 | f 的辅助指标 |
| **MSE** | 平均平方误差 | `mean((ŷ − y)²)` | g 的**回归**诊断（比赛等权 macro） |
| **配对比较** | 同一场比赛上的两个策略直接对比 | 差值 = 策略 A 损失 − 策略 B 损失 | 策略对比 |
| **Bootstrap 置信区间** | 反复重采样估计"这个差值稳不稳" | 比赛为抽样单元，2,000 次，seed 20261025 | 策略对比的不确定性 |
| **时间切分** | 用过去训练、用未来测试 | 按时间划六个角色 | A 集 |
| **独立比赛划分** | 一场比赛的所有前缀只能属于一个角色 | 以 `physical_match_id` 为分组单位 | 硬约束 |
| **数据泄漏** | 训练时看到了不该看的信息 | — | 见下 |
| **恒零基线** | "永远预测 0 收益" | 预测值恒为 0 | g 回归诊断的底线 |
| **市场赔率参考** | 博彩市场的隐含概率 | football-data.co.uk 的 Avg 报价 | 策略比较的参考行 |

### 本项目如何防泄漏（四条）

1. **角色隔离**：六个角色的比赛两两交集为 0；合格正文的精确 SHA 跨角色重叠为 0。
2. **标签隔离**：共享的赛果文件在使用标签前**按角色过滤**；validation/test 的标签不进入训练或模型选择。
3. **禁止输入**：g 的 schema 显式禁止 `outcome`、`realized_gain`、`candidate_after_*`。
4. **参数冻结**：推理期间 `parameter_updates_during_predict = false`。

### 为什么不同任务的 AUC 不可以直接比较

AUC 的含义**完全取决于标签**。早期有个流传的数字"g 的 AUC 0.544 vs Qwen3 的 0.918"——那个标签是**单标注者判读的"标题是否含本场预测相关信息"**，而 g 的输出是 Δ_f 分数。**两者目标不同，不能当作 g 的精度。** 这一点必须主动说明。

### 真实例子

**早期 C 集上的配对 bootstrap**（33 个切分 = rand30 + loco3，正文臂，验证集选 alpha，diff = 模型 − 基线，负 = 更好）：

| 对比 | 平均差 | 90% CI | 是否成立 |
|---|---:|---|---|
| GTE-small 正文臂 vs 来源均值 | −5.85e-5 | [−9.36e-5, −2.60e-5] | ✅ CI 完全低于 0 |
| GTE-small 正文臂 vs 恒零 | −6.05e-5 | [−9.55e-5, −2.45e-5] | ✅ |
| project vs 来源均值 | +1.82e-5 | 跨 0 | ❌ |

**且必须同时说明**：这 33 个切分**共享同一批比赛**，切分之间不独立，**CI 只描述切分重采样波动，不是严格的统计显著性检验**。

### 可直接使用的解释句

> 我们的主指标是 Log Loss。策略比较用的是以**比赛**为抽样单元的配对 bootstrap，2,000 次重采样。有两件事我要提前说清楚：第一，AUC 这个指标在不同任务之间不可比，因为它取决于标签的定义；第二，我们的 30 个随机切分共享同一批比赛，**不是 30 次独立实验**。
