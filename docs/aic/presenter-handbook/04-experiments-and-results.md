## E1：新版 f 的训练与评估

**研究问题**：把全文语义加入预测器，能否改善赛前概率预测？

**实验假设**：候选全文的 256 维语义向量携带赛前信息，应能改善预测损失。

**数据规模**：训练 f_train **294 场 / 521 篇**；选择 f_dev **74 场 / 137 篇**；评估 validation 193 场、test 320 场。

**模型版本**：
- 集合残差 MLP（26,823 参数，seed 47，best_epoch 1）
- GRU（67,079 参数，隐状态 64，seed 29，best_epoch 1）

**基线**：原始市场先验；校准先验（即 s0）。

**指标**：逐场等权 final Log Loss（越低越好）；辅助 Brier 与 accuracy。

**结果**：

| 模型 | validation 193 场 | test 320 场 |
|---|---:|---:|
| 原始市场先验 | 0.965245 | **1.020413** |
| 校准先验（s0） | 0.963980 | 1.022476 |
| 集合 f（选中） | 0.962041 | 1.022482 |
| GRU f（选中） | **0.958916** | 1.026598 |

**✅ 可以支持的结论**：
1. 在 **validation 193 场**上，新版 f（集合 0.962041、GRU 0.958916）**优于**校准先验（0.963980）与原始市场先验（0.965245）。
2. 集合 f 与校准先验在 test 上几乎相同（1.022482 vs 1.022476）——**文本几乎没有额外贡献**。
3. GRU 在 validation 最好，在 test 最差（1.026598）——**存在验证—测试不一致**。

**❌ 不能支持的结论**：
1. **不能说"新 f 在测试集上优于市场"**——恰恰相反，test 上原始市场先验最好（1.020413）。
2. 不能把 validation 的改善称作"已证明的泛化提升"。
3. 不能宣称 GRU 优于集合（分集合表现相反）。
4. 不能把 GRU 与集合的差异**纯归因于循环结构**——报告明确说两者**元数据使用存在差异**。

**对设计的影响**：`best_epoch = 1` 说明继续训练不能改善 f_dev → 指向"**监督信号不足**"而不是"训练设置错误"。这直接影响了后续的判优标准：**不能只看回归/训练损失，必须看完整策略**。

**评委可能怎么问**：
- *"为什么 test 上变差了？"* → 这是真实的验证—测试不一致。原因可能有：训练数据量小（294 场）、文本监督信号弱、测试期分布变化。**我们不做超出证据的因果归因。**
- *"旧 f 呢？"* → 旧 f 只在"有相同正文/claim 的共同子集"上比较（validation 19 场、test 6 场），**样本极小，不能做结论**。

## E2：新版 g 的训练与诊断

**研究问题**：能否训练一个选择器，估计候选正文的条件预测增益？

**数据规模**：g_fit **479 场 / 7,600 转移**；g_dev **160 场 / 2,846 转移**（合计 10,446 行 / 639 场）。**转移数不是比赛数。**

**模型版本**：7 个头（zero / train_mean / state_ridge / fulltext_ridge / local_metadata_refit_ridge / fulltext_mlp × 3 seed）。

**基线**：恒零基线（预测恒为 0）。

**指标**：比赛等权 macro MSE；辅助 Spearman 秩相关、正类符号准确率。

**结果一：回归指标**

| 头 | g_fit（479 场） | g_dev（160 场） | test（320 场） |
|---|---:|---:|---:|
| **恒零基线** | 0.00020807 | **0.00018271** | **0.00021162** |
| state_ridge | 0.00020628 | 0.00018614 | — |
| fulltext_mlp_seed20261027 | **0.0000067** | 0.00021990 | 0.00025242 |

**结果二：排序能力**

| 头 | g_fit Spearman | g_dev Spearman | g_dev 正类符号准确率 |
|---|---:|---:|---:|
| state_ridge | 0.2213 | **0.0096** | 0.5130 |

**结果三：标签分布**（集合 f 侧）：正 **5,904** / 零 **0** / 负 **4,542**。

**✅ 可以支持的结论**：
1. **训练—评估落差是真实存在的**：全文 MLP 在 g_fit 上 macro MSE 只有 **6.7e-6**（拟合极好），在 g_dev 上 **2.199e-4**、test 上 **2.524e-4**，**都差于恒零基线（1.827e-4 / 2.116e-4）**。
2. `state_ridge` 在训练侧有微弱排序信号（Spearman 0.2213），**在 g_dev 上消失（0.0096 ≈ 0）**。
3. 官方报告自己给出的定性结论："**两套全文 MLP 都能显著拟合训练标签，但开发/测试没有胜过零基线。这是训练—评估落差的直接证据；不能凭参数少认定容量不足。**"

**❌ 不能支持的结论**：
1. **不能说"g 学会了排序候选"**——当选中的头是 state_ridge，它按设计不给候选排序。
2. **不能说"所有信息价值估计方法都无效"**——只测了 7 个头、1 个标签定义、1 个数据规模。
3. 不能说"g 的精度是某个数"——不同头目标不同。
4. 不能把 state_ridge 的"同状态候选同分"当成 bug——那是**设计使然**（它的输入不含候选向量）。

**对设计的影响**：这直接导致开发集选定的策略是**一个只判断"继续/停止"的模型**，而不是"选哪一篇"的模型。报告明确指出这一点，冻结包也把它写进了限制。

**评委可能怎么问**：
- *"为什么参数量大反而更差？"* → 因为这不是容量问题，是**监督信号没有迁移**。报告原话就是"不能凭参数少认定容量不足"。
- *"零标签为什么是 0？"* → 是有效标签的实际结果，**代码未筛除零或负收益**；因为在连续概率空间上算差值，恰好为零的概率极低。
- *"4,540 条 failure_rows 是什么？"* → **都是 `input_preparation / sequence_not_eligible`，不是 4,540 次 f 执行失败**；gain = null。

## E3：完整策略比较（**核心实验**）

**研究问题**：把 g 放进完整选择策略后，最终预测表现是否优于简单基线？

**实验条件**：同一比赛集合 ｜ 同一候选池 ｜ **固定同一个 f** ｜ **采用预算 = 3** ｜ 指标 = 逐场等权平均 Log Loss ｜ 随机策略每场 10 seed 先平均再按比赛等权。

**结果**：

| 策略 | validation 193 场 | test 320 场 |
|---|---:|---:|
| 不采用正文（校准先验） | 0.963980 | 1.022476 |
| 固定顺序 | 0.962062 | 1.022446 |
| 随机采用 | 0.962063 | 1.022450 |
| **state-Ridge g** | **0.963420** | **1.021563** |
| 原始市场参考 | 0.965245 | **1.020413** |

**配对 bootstrap**（比赛为抽样单元，2,000 次，seed 20261025；差值 = 新 g 损失 − 随机损失，**负数更好**）：

| 对比 | 差值 | 95% 区间 | 判定 |
|---|---:|---|---|
| set / validation | **+0.001357** | [−0.000466, +0.003016] | 跨 0，**点估计为正（更差）** |
| set / test | **−0.000886** | [−0.002299, +0.000438] | 跨 0 |
| gru / validation | +0.004637 | [−0.002466, +0.011515] | 跨 0，更差 |
| gru / test | −0.004261 | [−0.009951, +0.001695] | 跨 0 |

**✅ 可以支持的结论**：
1. **在验证集上，state-Ridge 没有超过固定顺序与随机**（0.963420 > 0.962062 > 0.962063）。
2. **在测试集上，state-Ridge 点估计最低**（1.021563），比随机低约 **0.000886（万分之九）**。
3. **但配对 95% 区间包含 0**，所以这不是稳定优势。
4. **测试集上原始市场参考损失更低**（1.020413）。
5. **四个策略的验证集与测试集排序不一致**——这是一个真实存在的泛化问题。
6. 这套评估框架**能区分"点估计改善"和"统计上不显著"**，这是可运行的方法学成果。

**❌ 不能支持的结论**：
1. 不能说"已证明模型有效"。
2. 不能说"已证明优于市场"——恰恰相反，test 上市场更低。
3. 不能说"已证明优于随机"——CI 跨 0。
4. 不能说"已证明稳定盈利"——本实验不涉及任何经济收益。
5. 不能把 `all`（全部采用）当作与预算 3 成本相同的对照——报告明确说它是**无上限参照**。

**一个必须会解释的结构性事实**：
`state_ridge` 的输入不含候选向量，**在 334 个多候选决策状态中全部候选同分**，按冻结来源顺序破平。所以：
- 它实际学的是"**继续还是停止**"；
- 它的优势（若存在）**不来自"选择哪一篇"**；
- 冻结包自述："**不是全文排序模型**"。

**GRU 侧的对照更极端**：`local_metadata_refit_ridge` 在 test 320 场**只采用 10 次**，**115 场英超全部停止于未采用状态**。报告原话："**收益优势可能来自少读，不代表识别了更好的文章。**"

**对设计的影响**：这是本阶段最重要的实验结论——**"判断何时停止"与"判断选哪一篇"是两个不同的问题**，而当前开发集选定的策略只解决了前者。

**评委可能怎么问**：
- *"为什么测试集差异这么小？"* → 因为语料是文本监督极弱的环境。如实说数字：万分之九，且 CI 跨 0。
- *"市场参考为什么更好？"* → 两个可能：① 市场本身就是很强的先验（文献反复验证过）；② 我们的模型在这个数据规模上没有学到超越市场的文本增量。**另外必须说明：市场参考的报价时点未被验证（`prior_time_verified = false`），所以它不是严格同条件的对照。**
- *"那你们这套框架有什么用？"* → 它能明确区分"点估计改善"和"统计上不显著"，并且给出了同池、同预算、同预测器的严格对照协议。**这个协议本身是可复用的产出。**

## E4：顺序敏感性

**研究问题**：证据的阅读顺序会不会影响预测？

**数据规模**：完整池 **513 场 / 1,041 篇**；源顺序 + 5 个固定随机排列；两个 f 共 6,156 行。

**结果**：

| 模型 | 结果 |
|---|---|
| 集合 f | **最终 L1 = 0**（完全置换不变，符合设计） |
| GRU f | 多文 324 场最大 L1 均值 ≈ **0.001374**，最大 **0.0122995**，**无最高概率类别变化** |

**✅ 能支持**：集合结构确实做到了置换不变；GRU 的顺序效应**存在但很小**，且不改变最高概率类别。

**❌ 不能支持**：不能据此说顺序不重要——报告明确："**这些是历史采用顺序对照，不是事实发生顺序；后读不能解释为事件更新。**"

**对设计的影响**：说明在当前数据上，顺序带来的差异小于其他因素（如监督信号强弱）。

## E5：冻结演示与复现

**研究问题**：整套研究能否被独立重跑并得到同样结果？

**数据规模**：B 集 **160 场 / 342 篇**（= A 集的 g_dev 段）。

**结果**：

- **160 / 160** 案例真实推理成功，`selected_ids` / `stop` / `p_after` 与原冻结记录**逐条一致，最大概率差 = 0**。
- 364 个核心文件 SHA 通过；f 与 g 权重 bytes 与源完全一致。
- 10 个模型/策略模式在默认首场实际运行；fixed 采用 3 篇、all 采用 5 篇；对照不伪造 g 评分。
- prediction 期间 outcomes 读取被主动拦截，**触发 0 次**。
- 复制到 Windows 临时目录运行；审计钩子禁止访问原 D/E 盘，**违规 0 次**。
- 独立副本正文故意损坏后摘要校验**拒绝**；恢复后复验通过。
- **0 网络、0 外部 API、0 训练**。

**✅ 能支持**：冻结包**可复现**；模型权重未被静默修改；推理路径**不试图读取赛果**。

**❌ 不能支持**：
1. **160/160 ≠ 160 场预测正确。** 前者是"同一权重给出同一数值"，后者是"数值对不对"。
2. 不能当作 160 场独立前瞻测试。
3. 不能说明策略有效性。

**评委可能怎么问**：
- *"160 场都对了吗？"* → **必须纠正**：是 160 场**复算数值一致**，不是预测正确。这是两个完全不同的概念。
- *"怎么证明可复现？"* → 可以用 manifest SHA `dcb05e97…`、364 个核心文件 SHA 校验、以及"最大概率差 = 0"这三条。

## E6：早期文本表示基准（C 集）

> ⚠️ **版本提醒**：C 集是**早期数据**（51 场 / 92 篇 / 289 行），**与 A 集无交集**，数字**不可与 A 集混用**。

**研究问题**：用不同文本表示训练一个增益估计器，能否优于常数基线？

**数据规模**：**51 场 / 92 篇 / 289 行**（比赛级切分 39/6/6，行级 241/24/24）；来源域名 9 个（`leedsunited.com` 占 166/289 行 = 57%）。

**模型版本**：**35 种切分**（原切分 P0 + chrono + 3 个留一俱乐部 + 30 个随机）× **8 个编码器** × **7 个特征臂** = 56 个文本配置。

**基线**：恒零（0.00089320）、训练集均值（0.00089625）、来源均值（0.00088991）。

**指标**：比赛等权 macro MSE。

**结果**：

| 结论 | 数值 |
|---|---|
| 最低的文本配置 | project_tfidf_sparse 正文臂 **0.00094081** |
| 是否优于恒零基线 | ❌ **全部 56 个配置在 35 切分均值上都不优于恒零** |
| 唯一例外 | GTE-small 正文臂：平均差 **−5.85e-5**（vs 来源均值）/ **−6.05e-5**（vs 恒零），90% CI **完全低于 0** |
| 32 维 SVD 是否瓶颈 | 是。4000 维稀疏 TF-IDF 在 4 个文本臂上优于 32 维 SVD |
| 正则化敏感性 | alpha=10 对所有编码器**系统性欠正则**（验证集选 1000 占 67–75%） |

**✅ 能支持**：在这个数据规模与读出协议下，**文本表示没有带来可检出的增量**。

**❌ 不能支持**：
1. 不能说"所有文本方法都无效"——只测了 8 个编码器、2 种读出、1 个目标函数。
2. 不能说"负结果就是研究贡献"——需要可复用诊断才算贡献。
3. **不能把 C 集的数字与 A 集并列**。

**一个必须披露的技术细节**：`audit_crosscheck` 显示 **700 个对照点 `max_abs_diff = 0.0`**。这**只证明两次计算口径相同**，**不证明模型有效**。这句话在答辩时要主动说，否则会被追问。

## E7：早期标题/来源消融（C 集）

**研究问题**：标题通道携带的是不是"捷径"（来源/俱乐部身份），而非真实语义信息？

**结果（P0 原切分）**：

| 配置 | validation MSE | test MSE |
|---|---:|---:|
| 原标题（title_local_ridge） | **0.0007747**（全场最优） | 0.0021539 |
| 标题替换为训练均值 | 0.0011839 | 0.0014257 |
| 标题替换为全零 | 0.0012296 | 0.0014138 |
| **恒零基线** | — | **0.0012191** |

**✅ 能支持**：
- **标题通道在该切分上有害**：把标题换成常数后，test MSE 从 0.0021539 降到 0.0014257。
- **验证集最优模型在测试上落后恒零 0.000935**（0.0021539 − 0.0012191）。
- **30 次随机重排**在"实际有效模型"上选出 **15 种不同模型**——模型选择极不稳定。

**❌ 不能支持**：
1. 报告自己的警告必须一起说："**改变切分也会改变训练量、目标分布和球队覆盖。反转减弱不能单独证明来源捷径，反转保留也不能证明任何正确模型都会失败。**"——所以"来源捷径"目前是**假设**，不是结论。
2. 不能把 30 次重排当成 30 个独立测试集（**它们共享同一批比赛**）。

**对设计的影响**：这是"验证集选模型 → 测试落后基线"最干净的单点证据，也是新版坚持"按策略损失选阈值"的动因之一。

## E8：早期收缩诊断（C 集）

**研究问题**：把文本模型的预测向常数基线收缩（`ŝ' = w·ŝ + (1−w)·b`），能否改善？

**方法**：候选权重 `{0, 0.05, 0.1, 0.25, 0.5, 0.75, 1}`，**仅验证集选择**；测试集不参与权重/模型选择。共 6 个命名切分 + 30 次重排。

**结果（命中率最高的部分）**：

| 切分 | 验证集选出的文本权重 | 实际退化到 |
|---|---:|---|
| P0_original | 0.75 | fulltext_masked_ridge_toward_source_mean |
| chrono_within_cohort | **0.0** | train_mean（**退化为常数**） |
| loco_arsenal | 0.1 | fulltext_state_ridge_toward_train_mean |
| loco_chelsea | **0.0** | source_mean（**退化为常数**） |
| loco_liverpool | 0.5 | fulltext_state_ridge_toward_source_mean |
| global_time_51 | **0.0** | zero（**完全退化**） |

**✅ 能支持**：
1. **6 组中有 3 组验证集选择的权重为 0**——即文本通道完全退化到常数基线。这是"文本没有增量"的独立证据。
2. P0 原切分 6 场测试上，全文方案相对 `no_information` 平均差 **−0.011849**，95% CI **[−0.020011, −0.003814]**（改善 3 场、变差 0 场、相同 3 场）。

**❌ 不能支持**：
1. 原文件自述："已查看小样本的**探索性** bootstrap，**不能据此宣布新模型独立验证成功**。"
2. 不能忽略另一个事实："**回归 MSE 最优不一定对应策略 loss 最优；收缩可能帮助，也可能过早停止并错过有用证据。**"
3. 30 次重排在**实际有效模型**上分散到 **15 种**（含 zero / train_mean / source_mean 直接胜出）。

## E9：早期真实历史策略比较（D 集）

> ⚠️ **D 集是 290 场 Understat EPL 历史重建集，与 A 集无交集。**

**数据规模**：380 场真实比赛 → 7 个时间折 → **290 场测试比赛**。

**预算与结果**：

**主预算 0.05 / 最多两次请求**：

| 方法 | 平均 log loss | 平均查询次数 |
|---|---:|---:|
| 不查询 | **1.080229** | 0 |
| 原 global strict-VoI | 1.094743 | 0.417 |
| context strict-VoI | 1.087068 | 0.690 |
| context residual strict-VoI | 1.086871 | 0.572 |
| **context residual 固定顺序全查** | **1.086803** | 2.000 |

**第二个必读结论**：**同表内固定顺序全查（1.086803）优于条件 VoI（1.086871）**。

**低预算 0.03 / 最多一次请求**：context 策略纯 log loss **1.079009**，略优于不查询的 1.080229；但**损失加成本为 1.085854，仍高于不查询**。

**冻结后期新取得 50 场**：修正策略**全部不查询**，log loss **1.090590**，与不查询相同。

**✅ 能支持**：主干结论是**负结果**——在这个预算与预测器配置下，条件 VoI 未带来改善。

**❌ 不能支持**：
1. 不能说"所有预算、所有指标都没有改善"——低预算下纯损失有微幅改善，**不能遗漏这个局部正项**。
2. 不能说这是独立确认实验——报告自述"**这些是看到诊断后再次使用的开发比较，不是新的独立确认实验**"。
3. 不能跨轮比较 utility 数字——不同轮次成本权重不同。
4. **不能把 D 集的 290 场与 A 集的 1,520 场放在同一张表里**。

## 五个"为什么不能混用"（高频考点）

| # | 问题 | 答案 |
|---|---|---|
| 1 | 为什么 51 场旧实验与 1,520 场新版不能直接混用？ | **两个无交集的数据集、两代模型、两套标签定义**。混用会同时污染样本量口径与结论 |
| 2 | 为什么 160 场冻结演示 ≠ 160 场独立前瞻测试？ | 演示只是**用同一权重重跑并逐条比对数值**；前瞻测试要求赛前冻结、赛后结算、且样本未被开发暴露 |
| 3 | 为什么 700 个对照点复算一致只能证明复现一致性？ | 它比的是"两次计算是否同尺"，不是"计算对不对" |
| 4 | 为什么"近常数化"是估计器诊断而非"所有方法无效"？ | 只测了 7 个头、1 个标签定义、1 个数据规模。`state_ridge` 的同分是**设计使然**而非缺陷 |
| 5 | 为什么负结果提供研究信息，但不自动构成原创性？ | 负结果的价值取决于三点：① 有可复核协议；② 边界在文献中未被报告；③ 给出可复用诊断。**本项目第 ③ 点只完成了一部分**——协议与诊断有，但门控消融因样本量不足做不了 |
