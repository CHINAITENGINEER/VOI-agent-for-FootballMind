## 一、最重要的一件事：项目存在两套系统，不要混为一谈

FootballMind 在研究过程中演进出了两代系统。**它们的模型、数据、评估口径完全不同，任何对外表述都必须先说明在讲哪一代。**

| | **旧版：在线探索原型** | **新版：全文序列研究** |
|---|---|---|
| 时间 | 2026-09 至 2026-10-10 前后 | 2026-10-25 完成并冻结 |
| 预测器 f | `quoted-entity-count-semantic-match-residual-f-v1`（实体证据 + 引文计数 + 语义匹配 + 残差） | `set_residual_mlp` / `gru`（**全文语义表示 + 状态 + 顺序**的神经预测器） |
| 选择器 g | `historical-state-candidate-gain-v1`：Ridge + 15 个显式关系特征 + 标题 TF-IDF | `sequential-postread-g-v1`：1140 维输入（含**候选全文向量**），多个头（state_ridge / fulltext_ridge / fulltext_mlp × 3 seed） |
| 看的是标题还是全文 | **g 只看标题 + 已采用证据状态**；f 看结构化 claim | **g 看候选全文向量**；f 看全文向量 + 22 维元数据 |
| 数据规模 | postread 语料：51 场 / 92 篇 / 289 行 | 全文序列语料：1,520 场 / 3,001 篇 / 4,521 前缀 |
| 是否有候选排序能力 | ❌ 实测近常数（跨度 0.004435），排序近随机 | ⚠️ state_ridge 按设计**不给候选排序**（同状态候选同分）；fulltext 头可以排序但未证明有效 |
| 当前状态 | 保留为历史诊断，**不再作为主线** | **当前主线**，已冻结成可演示的便携包 |

**三条硬性禁忌**（评委面前一旦违反即为硬伤）：
1. **不得**把旧版在线运行案例（如"克罗地亚 vs 西班牙"读到官方正文）说成新版全文模型的联合验证。
2. **不得**把新版全文 MLP 的单场概率变化案例，与"集合预测器 + state-Ridge"的完整策略评估说成同一个模型的实验结果。
3. **不得**把 160 场演示语料规模当作训练集规模，也**不得**把历史重建数据说成已完成的赛前前瞻验证。

## 三、模型资产登记表

### 3.1 新版预测器 f

| 项 | `set_residual_mlp`（集合预测器） | `gru`（序列预测器） |
|---|---|---|
| 架构 | 置换不变的集合残差 MLP | GRU（隐状态 64） |
| 输入 | 256 维全文表示 + 16 维生效元数据 + s0 先验 | 同上，按顺序逐步输入 |
| 总参数 / 可训练 | **26,823 / 26,819**（含 4 个基础校准参数） | **67,079 / 67,075** |
| 训练规模 | f_train 294 场 / 521 篇 | 同 |
| 选择依据 | f_dev 比赛等权前缀 log loss | 同 |
| 选中 seed / epoch | seed 47 / **best_epoch = 1** | seed 29 / best_epoch = 1 |
| 优化器 | AdamW，lr 0.001，weight_decay 0.01，betas [0.9, 0.999]，eps 1e-8，grad clip 5.0 | 同 |
| 批次 / 上限 | 32 场比赛；最多 200 epoch；patience 25 | 同 |
| 损失 | 交叉熵，先对每场全部前缀平均（**含 s0**），再按比赛等权 | 同 |
| s0 的含义 | **校准后的市场先验；无文本残差** | 同 |
| 关键性质 | `parameter_updates_during_predict = false`；初始残差头为零（epoch0 等于冻结校准先验）；基础校准器在正文训练阶段冻结 | 同 |

> **注意 `best_epoch = 1`**：f_dev 上选择出的检查点是第 1 个 epoch。这说明**在当前的监督信号与数据上，继续训练不能改善 f_dev 损失**。这是重要事实，不要回避。

### 3.2 新版选择器 g

**统一输入：1140 维**，由 13 个块拼成（来自 `models\g\feature-schema.json`）：

| 块 | 起止 | 维度 | 含义 |
|---|---|---:|---|
| `current_f_probabilities` | 0–3 | 3 | 当前 f 给出的主/平/客概率 |
| `entropy` | 3–4 | 1 | 当前概率分布的熵 |
| `adopted_count` | 4–5 | 1 | 已采用正文数 |
| `remaining_count` | 5–6 | 1 | 剩余候选数 |
| `remaining_budget` | 6–7 | 1 | 剩余预算 |
| `adopted_mean_embedding` | 7–263 | 256 | **已采用**正文的均值向量 |
| `adopted_mean_metadata` | 263–285 | 22 | 已采用正文的元数据均值 |
| `current_f_hidden_state` | 285–349 | 64 | 当前 f 的隐状态 |
| `candidate_embedding` | 349–605 | 256 | **候选**正文向量 |
| `absolute_difference` | 605–861 | 256 | 候选与已采用均值的绝对差 |
| `elementwise_product` | 861–1117 | 256 | 候选与已采用均值的逐元素积 |
| `candidate_metadata` | 1117–1139 | 22 | 候选正文元数据 |
| `maximum_adopted_cosine` | 1139–1140 | 1 | 与已采用证据的最大余弦相似度 |
| **合计** | | **1140** | `state_width = 349`（前 8 块） |

**明确的禁止输入**（`forbidden_inputs`）：`outcome`、`realized_gain`、`candidate_after_probability`、`candidate_after_hidden_state`。
`current_hidden_source` = "同一冻结 f 在当前已采用前缀下的隐状态；**不含候选加入后的状态**"。

**七个已训练的头**（`models\g\model.json`）：

| 头 | 参数 | 输入 | 阈值 | 选中 epoch |
|---|---:|---|---:|---|
| `zero` | 0 | 常数 0 | 0.0 | — |
| `train_mean` | 1 | 训练集均值 | 0.003 | — |
| `state_ridge` | **350** | 349 维状态（**不含候选向量**） | 0.0 | — |
| `fulltext_ridge` | 1141 | 1140 维（含候选向量） | 0.01 | — |
| `local_metadata_refit_ridge` | 52 | 51 维元数据 | 0.01 | — |
| `fulltext_mlp_seed20261025` | 154,369 | 1140 维，1140→128→64→1 | 0.003 | 43（跑 68） |
| `fulltext_mlp_seed20261026` | 154,369 | 同上 | 0.0 | 1（跑 26） |
| `fulltext_mlp_seed20261027` | 154,369 | 同上 | 0.01 | 42（跑 67） |

- **开发集选定的策略是 `state_ridge`**（阈值 0，预算 3），在 g_dev 160 场上 `mean_final_log_loss = 0.910384`，`mean_updates = 0.75625`。
- **演示默认模型是 `fulltext_mlp_seed20261027`**（阈值 0.01，预算 3）。
- **`alpha = 10.0`** 对所有 Ridge 头相同；标准化**只在训练折拟合**。

> **两个容易被误读的关键点**：
> 1. `state_ridge` 的输入**不含候选向量**，所以它在**同一状态下给所有候选相同分数**。冻结包 `bundle-config.json` 明确写："仅按当前状态估计采用/停止；同状态候选同分，按冻结来源顺序破平，**不是全文排序模型**"。因此它的优势（若存在）来自**判断何时停止**，不来自**选择哪一篇**。
> 2. 它是**按 g_dev 的完整策略损失**选出的，不是按回归误差选出。

## 五、术语口径统一表

| 术语 | 本项目中的**唯一**含义 | 不要混淆为 |
|---|---|---|
| **条件预测增益** Δ_f | `L_before − L_after`，同一个冻结 f 在采用候选正文前后的损失差 | 不等于经济收益、不等于因果效应、不等于相关系数 |
| **s0** | 空证据状态（未采用任何正文） | 不等于"原始市场参考"——s0 是**校准后**的市场先验 |
| **采用**（adopt） | 把该正文向量加入状态并让 f 重算概率 | 不等于"读过"（g 在评分时已能读全文） |
| **状态前缀** | 一场比赛在某个采用顺序下的证据快照 | 不是独立比赛 |
| **冻结** | 参数在推理期间不变（`parameter_updates_during_predict = false`） | 不等于"不许调用" |
| **已验证** | 有适当实验设计与对照支持某结论 | 不等于"代码能跑"或"训练完成了" |
| **历史重建** | 用事后归档材料重建当时的信息可用性 | 不等于"赛前前瞻验证" |
| **复现一致性** | 同一冻结模型重跑得到同一数值 | 不等于预测准确率高 |

## 六、本文件与其他文档的一致性约束

1. 任何文档提到"1,520"时必须同时给出单位（比赛）；提到"3,001"或"4,521"时必须给出单位（篇 / 前缀）。
2. 任何文档提到"24,911"时必须写成"具备结构化监督的比赛"。
3. 任何文档提到 160 场演示时必须标注"**数值复现一致性，不是预测正确率**"。
4. 任何文档提到"市场参考"时，必须说明其 `prior_time_verified = false`。
5. 任何文档**不得**将 state_ridge 描述成"候选排序模型"。
6. 任何文档**不得**把 C 集（51 场）与 A 集（1,520 场）的数字并列在同一条曲线或同一张对照表里。
