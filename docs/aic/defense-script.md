# FootballMind 答辩稿与演示安排

定位：通用算法创新赛研究原型。主讲约 7 分钟，可缩为 5 分钟；问答另计。材料以已经验收的归档为准，不使用现场结果改变冻结实验，不将回放称为实时运行。

## 主讲稿

### 0:00—0:45：用户真正交给系统的任务

> 用户只输入一场比赛。系统需要自己决定下一步查什么、值得付出多少成本，以及何时停止。
>
> 比如一支球队已经提前出线，我们可能想知道它是否轮换。但提前出线本身并不等于实力下降；已经知道首发以后，再读一篇转载也未必有价值。因此，我们研究的不是给所有比赛固定输入一张特征表，而是信息获取本身的决策过程。

展示：项目标题与“比赛 → 候选 → 估值 → 获取 → 更新 → 再决策”六个步骤。不要让评委先面对角色命名、数据库表或测试数量。

### 0:45—1:35：为什么需要可计算的信息价值

> 在开放网页环境中，工具返回可能是正文，也可能是空结果、目录或错误信息。查询还有成本，下一步能看到哪些链接也会随查询变化。
>
> 我们用当前已读历史来估计一个请求可能返回什么，再计算这些返回预期会降低多少概率决策损失，并扣除成本。信息价值由模型估计。支持不足时输出未知，不把语言模型的一句“看起来有用”换算成收益百分比。
>
> 这里的自主性是机器在当前能力范围内选择和停止。来源目录、预算及当前候选规则仍有人为设计，尚未实现不受限制的语义探索。

展示：一个“有支持的正值／有支持的非正值／未知”三分状态表；未知不能标为低风险或零价值。

### 1:35—2:40：核心方法

> 正文响应模型条件于初始概率、当前请求和实际读过的有序历史。查询前的概率分支与查询后的后验更新使用同一冻结模型，从而可以核对预期和实际返回。
>
> 还存在一个重要问题：目录页本身可能完全不改变胜率，却能找到值得读取的文章。只看一步收益会跳过它。因此，我们从训练轨迹学习候选发现的转换，再向前看一次后续查询，计算直接收益加后续收益，减去两次请求成本。
>
> 未知未来 URL 用训练请求类近似规划，不能直接拿去执行。实际链接出现后，再对真实请求重新估值。两步估值只覆盖有支持的有限子策略，不是整个互联网的最优策略。

展示：主公式 `两步值 = 一步值 + 分支条件下可行后续查询的正净收益期望`，同时显示请求预算。完整版公式在 [项目说明](submission-brief.md)。

### 2:40—3:50：合成实验回答了什么

> 主实验使用 960 个训练场景、240 个独立留出场景，五种策略共用初态、预测器、潜在返回和成本。三档预算产生 3,600 条运行，但独立留出样本仍然只有 240 个。
>
> 在预算 0.095 时，两步策略平均查询 0.846 次，固定与随机策略都是 1.792 次。损失加成本分别为 0.947120 和 0.980864；固定查询的纯预测损失略好。
>
> 因此，这个结果支持了在所设计机制中的成本与质量权衡，不支持所有指标都提高。该实验只有一个初始发现动作，后续两篇是相关转载，也没有证明一般多工具排名。实现曾因历史 URL 唯一标识而失败，修复后的结果仍来自同一开发留出集，不能当成新的独立确认。

展示：预算 0.095 的五策略表；附一个“一次请求预算不启动发现链”的反例。若压缩到 5 分钟，仅保留两步与固定查询两行，并口述完整表已提交。

### 3:50—4:45：真实负结果不能省略

> 在旧开发区 290 场的两次请求主预算下，严格 VoI 的预测损失曾达到 1.115840，不查询为 1.080229。后续上下文修正降低到 1.086871，仍然落后。一次请求预算下也有局部改善：上下文策略纯损失为 1.079009，略优于不查询，但加入成本后未占优。
>
> 这说明数学上正的模型期望值，不保证模型在真实环境里估计得准确。另一批冻结后取得的 50 场历史比赛中，修正策略全部不查询，与不查询相同，也不能算学会了主动获取。我们保留这些负结果，没有通过降低成本、删除失败或重新命名数据分区来制造结论。

展示：真实历史损失表，不与合成表混成一条“总体提升”。不同轮次使用的综合成本权重不同，不跨轮比较 utility 数字。

### 4:45—6:05：真实后端现在能做到什么

> 实际执行中，三场比赛先由原始市场报价形成初态，并与官方原始比赛身份核对。程序再生成候选，按未知价值下的有限探索获取信息。三场共发生八次真实请求。
>
> 克罗地亚对西班牙的运行读到官方正文，从内容产生一条关于 Budimir 的后续查询，并实际执行；后续连接失败也留在记录中。苏格兰对斯洛文尼的运行从足协目录发现并读到赛前发布会，同时保留了青年队文章的无效尝试。
>
> 这证明实际内容能够进入下一步行动，但这些真实请求还没有训练好的数值 VoI。三场概率未改变，独立赛果在冻结记录中仍然待结算。我们将它作为工程闭环展示，不作为真实预测收益证明。

展示：克罗地亚归档的一次完整回放，显示初始候选、实际文章、原文锚、后续查询失败、成本与最终暂缓；同时显示“离线回放”和“真实查询价值未知”。

### 6:05—7:00：贡献、限制与交付

> 这个项目的研究贡献候选是：把已读历史条件化的响应模型、信息发现的后续价值，以及未知条件下的实际执行和停止接成一条可审计链。VoI、主动特征获取和工具调用都不是我们首创；MCP 或增加代理角色也不算算法贡献。
>
> 当前交付包括可运行后端、冻结实验、原始页面、逐步决策、失败记录和零网络回放。它已经可以被他人检查和复现，但真实开放新闻的成本收益还需要更多合格轨迹、独立赛果和冻结确认实验来回答。
>
> 我们最终要检验的，是机器能否在当前信息状态下判断什么值得继续查，而不是让用户替系统制定每场比赛的调查清单。

## 演示操作与准备

封版的统一入口为 `python -m football_agent.footballmind`。以下命令使用已归档输入；输出目录必须是新的目录，避免覆盖已冻结结果。完整操作说明见 [冻结后端入口](../agent/backend-release.md)。

答辩现场优先使用一键演示包。它把自主机制边界、冻结语义证据验收、合成两步 VoI 和真实归档回放收束到一个目录，并在清单中记录每项证据类型、哈希和 claims boundary：

```powershell
python -m football_agent.footballmind demo --output var/aic-demo/bundle-<date>
```

该入口固定为零网络、零语义模型调用；通过只表示证据链和机制回放一致，不表示真实足球预测收益。查看 `demo-manifest.json` 后，按 `report.md` 的三分钟顺序展示；评委追问时再运行下面的单项命令。输出目录必须是新的目录，不能覆盖既有演示包。

```powershell
python -m football_agent.footballmind matches
python -m football_agent.footballmind replay --match "克罗地亚 vs 西班牙" --output var/aic-demo/croatia-replay
```

第一条列出已经绑定的比赛；第二条严格零网络重建已有真实轨迹。查看输出的 `result.json` 及 `replay/report.md`。原始真实材料也可直接核对 [克罗地亚运行报告](../../var/parallel/agent/round180/live-batch/match-2981455/report.md)。

合成机制可使用下面的独立离线入口，直接加载冻结模型，不现场拟合：

```powershell
python -m football_agent.footballmind mechanism --case two-step --output var/aic-demo/two-step
python -m football_agent.footballmind mechanism --case one-step --output var/aic-demo/one-step
python -m football_agent.footballmind mechanism --case one-request --output var/aic-demo/one-request
python -m football_agent.footballmind mechanism --case actual-no-link --output var/aic-demo/actual-no-link
```

四个案例分别展示两步查询链、单步策略不启动、请求预算不足时不启动、实际目录无链接时不执行假想 URL；输出明确标记为合成机制。主讲只演示前两例，后两例用于问答。原始案例依赖的初态模型在封版时按原确定性定义恢复并核对策略声明，未增加独立样本。全部比较数字见 [封版重算证据表](../../var/parallel/agent/round181/evidence/experiment-table.md)，它保留合成、真实历史和真实未结算记录的区别。无需在七分钟内运行全量实验。

`analyze` 与 `settle` 是另外的联网动作，不属于默认演示；已过预测截止的比赛不能重新进行赛前分析。现场网络失败时保留失败并使用预先准备的回放，说明来源和时间，不调整种子重跑至出现漂亮路径。

## 评委可能追问的问题

**VoI 已经研究很多年，你们究竟创新了什么？** 不是首次提出信息价值，也不是首次主动获取特征。当前具体工作是带已读正文历史的响应建模、候选发现的有限后续价值，以及它们在真实获取时钟和可回放执行中的结合。合成机制已验证，但论文级新颖性和相对既有方法的优势尚未充分建立。

**为什么不是一个普通爬虫加足球预测器？** 研究接口显式比较当前候选的获取后风险与成本，并可重新选择或停止；合成实验已经运行数值策略。与此同时，真实新闻模型尚未训练，当前真实执行仍是有限探索。我们不会把真实爬取成功本身算成数值选择能力。

**候选和主题词表也是人写的，怎么叫自主？** 用户无需逐场指定调查问题，但系统仍受来源目录、规则和有限主题提取的限制。算法负责在这些候选及后续发现中进行选择，不代表已经摆脱全部人为表示。苏格兰正文相关却未被五主题词表提取的失败正说明这个边界。

**LLM 在哪里？是不是把普通代码叫 Agent？** 本版 Agent 指维护状态并序贯采取信息动作的决策主体，不要求每个环节必须由 LLM 实现。已经实测的路径采用数值策略和确定性工具，没有声称 LLM 自主语义研究已完成。未来 LLM 可改进候选提议，但其收益必须另作同条件对照。

**为什么伤病收益高、天气收益低，是手工给分的吗？** 没有按主题设置收益常量。合成实验中的条件价值来自冻结训练返回与结果关系；情境及信号机制本身是设计出来的。因此它证明机制可以学到条件差异，不能直接证明真实伤病比天气更重要。

**目录页不改变后验，后续价值从何而来？** 来自学到的候选转换及后续正文的风险下降。目录只打开后续动作，不直接更改胜率。成本两次都计；只够一次查询、实际没有链接或失败时，不执行假想正文。

**未知信息被忽略，会不会错过真正最重要的文章？** 会，当前系统不能证明开放世界最优。未知项保留为未知；已有正收益受限子策略可以执行，缺少完整支持时不发全局停止证明。真实获取还有独立的有限探索额度。

**真实实验既然没有提升，为什么还有参赛价值？** 可提交的价值是一个可检验的研究原型、有限机制的明确证据和真实失败分析。它尚不支持“真实效果领先”的主张。是否达到具体赛事的竞争要求需要知道该赛事标准，不能凭本材料承诺获奖。

**随机策略和固定策略分数一样，是不是对照太弱？** 在这一合成设计里，初始只有一个发现动作，后续两篇是同一个信号的转载，因此两者等价。这支持发现与停止机制，不能替代广泛多工具排名对照。没有完成的 LLM 启发式、更多 AFA 方法和 oracle 对照不列为已完成实验。

**是不是看了测试集再修，结果不可信？** 实现缺陷在开发留出运行中暴露，我们保留首次失败、中间失败和修复结果，明确仍是同一开发留出集。数据、种子、阈值和成本未改，但这也不是未见数据上的独立确认。

**置信度、风险等级或停止证明可靠吗？** 本版报告的是模型条件值与支持状态，参数不确定性和真实概率校准尚未成立。预算耗尽是 halt；信息支持不完整是 defer；只有满足有限菜单条件才能作有限范围停止。它们不能互换成“高置信度”。

**三场结束以后就能证明收益了吗？** 不能。可以补齐独立标签、计算单次轨迹的结果损失，但三场既不足以可靠拟合，也不足以验证策略优势。重复运行不会增加独立比赛数，而且选择性日志并未覆盖所有未查询返回。
