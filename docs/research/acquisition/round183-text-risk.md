# Round183：开放正文的经验信息价值闭环

本项是用户在原十轮工程收敛结束后授权的一项算法攻坚任务。原十轮剩余轮次仍为零，
不重启常规工程排期。工作范围是“给定比赛，由 Agent 自主决定查询、更新与停止”；
没有前端、额外爬虫框架或结构化模型竞赛。Round182 发布包保持原样。

## 交付判断

实现并验证了开放请求的经验风险价值桥：固定正文预测器 → 样本外实际返回重放 →
有符号风险差 → 条件经验估值 → 原运行器选择实际动作 → 实际返回更新 → 再规划。
旧工程模块已有有符号 OOF、条件回归与同版本监督；本项复用统计，而不是重新把这些
能力命名为创新。新增接线通过测试与归档回放，但**没有取得真实文本效益，也没有
在本次合成开发复验中胜过原条件响应策略，因此不切换默认部署**。

## 数学对象与执行边界

对同一个冻结预测器 f、读前状态 s、当前实际可见请求 a、其实际返回 o 和独立赛果 y：

```
delta = log f(s + o)[y] - log f(s)[y]
residual = delta - model_EVSI(s, a)
estimated_gain = model_EVSI(s, a) + conditional_mean(residual)
net_gain = estimated_gain - declared_cost
```

delta 是该预测器的 log-loss 改善，可以为负。`TextRiskCalibrator.fit()` 自己重放 f
重算 delta，拒绝调用者提交的 delta、预测前后概率和 residual。来源/请求聚类、已读
有序正文 token、当前概率置信桶及原模型 EVSI 桶构成读前上下文；待查询正文与赛果
不进入估值。复用 `round9_residual.residual_summary`，同一比赛在一个上下文内只贡献
一份平均权重。精确重复去重，矛盾的同一实际返回拒绝。

这一估计不是 Bayes 最优信息价值，也不是新提出的信息价值理论。增量预测损失用于
动态信息选择已有研究，例如 [DIME，ICLR 2024](https://arxiv.org/abs/2306.03301)。
本项目此处的工作是将监督、开放请求、实际返回、运行时可见性和可重放执行连接起来。

只支持 log loss 的单步经验估值。未拟合/未支持返回、来源或历史保持 UNKNOWN；
不把缺支持引起的“概率不更新”记为正文价值零。仍沿用原正文核的支持阈值和精确有序
历史，这也意味着本项没有解决真实长历史的稀疏支持与文本泛化。

`TextVOIPolicy(..., risk_model=...)` 可选启用这一路径。选择用经验净改善，实际概率
仍按原 f 的冻结返回分支更新；不混用没有相应监督的两步发现模型。经验模式的
`gross_evsi`、预测前后真实风险和停止证书均为空，原模型 EVSI 单独保留供诊断。
有 UNKNOWN 或菜单不完整时继续明确 defer，不把它解释为已经穷尽开放信息。

## 本次开发复验：完整保留失败

原 Round178 的 900 场构造训练预测器不重训；已看过结果的 300 场旧合成留出按固定
顺序重用为 B=120 经验拟合、C=60 诊断、D=120 开发复验。C 不选择门槛，min_support=12、
shrinkage=20、成本与预算预先冻结。原合成时钟只跨几小时，无法形成真实前向窗口，
所以 C 虚拟平移两天、D 平移四天，原时钟完整保存在 `clock-mapping.json`。
这不是新比赛、独立盲测或真实历史时间证据。

每个策略共享同一 f、免费上下文、ABC 有限菜单和相同返回。共五策略、两预算、
120 场，1,200 条轨迹；原四策略在 D 上的 960 条结果重现旧实验。请求费用每次为
0.08 模拟损失单位，不是人民币、美元或实测 API 账单。

| 预算 0.24 / 最多三次请求 | 平均 log loss | 平均请求 | log loss + 费用 |
|---|---:|---:|---:|
| 原条件响应信息价值策略 | 0.620898 | 1.258333 | 0.721564 |
| 新经验风险估值策略 | 0.641430 | 1.125000 | 0.731430 |
| 固定顺序全查 | 0.600655 | 3.000000 | 0.840655 |

较低预算 0.08 / 一次请求下，新旧数值策略结果相同。较高预算中新策略少查，但综合
目标比旧策略差 0.009866；15 场因经验支持 UNKNOWN 停止继续取得信息。不能仅以少查
宣称更有效，也不能只比较固定全查而隐藏较强的原策略。
真正出现查询序列差异的是另外 16 场：经验策略将 A 后面的 C 判为非正而省去；其中
10 场预测损失变差、6 场变好。不能将这一比较差异归因于上述 15 场 UNKNOWN。

B 的 1,800 条监督中，1,784 条模型支持、16 条未知；381 条实质负改善保留。
C 的 900 个转移中 698 支持、202 UNKNOWN。估计负值桶的 188 条转移（55 场）平均
估计为 -0.085579，实际平均却为 +0.165414。这直接说明该经验估计没有建立可靠校准，
并可能漏掉有益信息。所有 B 样本处于一个合成 UTC 周，不能声称周聚类标准误或个体
条件覆盖保证。名称叫 calibrator 不等于已经证明校准。

完整逐场轨迹、分箱和负结果在 `var/parallel/agent/round183/evaluation/`；
`verify_results.py` 独立重算比分损失、成本、时间映射、身份与模型绑定，不重训。

## 真实数据探查的结果

6 个发现查询与 6 次目标 HTTP 抽样，3 次成功、3 次连接超时，失败未重试。
取得 Austria–France facts 与 Netherlands–England preview 两篇官方历史正文，
以及包含 51 个原生比赛 ID、36 场小组赛的官方结果索引。
这些是候选资料，不是 36 个完成文本监督的比赛。

两篇正文实际于 2026-10-06 捕获；官网发布/修改字段是来源声明，不能证明赛前原始
版本未被改动。严格历史快照资格为零，没有导出它们作为真实经验训练行。
已有三场真实赛前运行的合格独立标签与真实正文训练样本仍为零。本次机制参数和
合成校准件没有进入真实路径，真实数值 VoI 仍保持 UNKNOWN。

## 验收与下一笔必要投入

验收包括：正模型 EVSI、负经验 gain 的查询否决；未读内容不泄漏；三时钟和同场
隔离；同一 f 的实际更新；实际正文产生后续候选；已尝试/重复信息的重新估值；
校准件篡改与未来模型拒绝；新归档零网逐字回放，以及三份旧真实运行的兼容回放。
自动验收入口为 `var/parallel/agent/round183/verify_round183.py`。

后续最高收益的投入是一个明确的真实、按比赛隔离的正文监督数据集，包含同场多个
可竞争请求、实际时钟、原始返回和独立赛果。先测正文预测器实际支持覆盖，再决定
是否研究新的部分正文表示；不要先套更多 estimator。只有当新真实数据上的样本外
收益、支持与同预算比较成立，才有理由启用经验值作为真实部署选择依据。
本项不以降低支持阈值、重用 D 调参或把历史回采改名为实时样本来消除这个缺口。
