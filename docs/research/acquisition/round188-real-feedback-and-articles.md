# Round188：真实结果反馈与正文驱动的后续查询

本项处理两个直接阻断自主信息获取学习的问题：真实赛前响应缺少独立赛果监督，
以及新正文解析器输出的 article 无法进入旧证据投影。未重新拟合构造模型或调整
Round187 的确认结果；原十轮工程收敛约束不重置。

## article 到后续候选的运行链

独立复现确认，同一段原始文章经过新闻解析 v1（kind=page）时，旧证据投影可
提取内容；经过新闻解析 v2（kind=article）后反而被拒收。此前新解析器能读到
正文，但这条类型断点使正文无法参与下一次候选生成。

新增显式 `match-evidence-extraction-v3`，默认仍为原 v2，旧档按记录的版本回放。
v3 从已准入正文的精确段落位置构建来源断言，保留每段发布时间、修改时间、无
时区日期原文以及实际采集和可用时间。未通过段落位置或时间检查的内容不能贡献
引文、查询词或版本关系；未核实语言/球队关联的段落单列为未绑定来源文字。

以下关系只表示可观察信号，不自动决定真相或价值：

- 相同引文是文字重复，不增加独立证实次数。
- 同 URL 不同字节是来源版本变化，不表示较新内容一定替代较旧内容。
- 相反词面是待核实的冲突，不等于已证明的语义矛盾。
- 发布时间不代替事实有效时间；“已出线”不推导出“轮换”或“实力下降”。

符合目标范围的已读信息可通过现有 `EvidenceDocumentCandidates` 形成后续查询，
查询仍交给已有预算选择机制。v3 不给这些候选硬设信息价值，也不修改冻结正文
预测器的状态或概率。未知值探索与学习得到的数值 VoI 选择继续分别记录。

新版本可由实际采集 API/CLI 的 `evidence_version` / `--evidence-version` 显式
选择。典型组合为 `news_projection_version=2` 和
`evidence_version="match-evidence-extraction-v3"`。每次运行归档实际选择的版本，
重放使用相同版本，而不从当前默认重新推断。

## 验收与后续

正文运行集成已覆盖“原始 HTML→新闻 article→精确证据→新查询候选→预算内实际
执行→归档逐字回放”。这是禁网构造机制测试，不冒充新的真实联网运行或策略收益。
真实旧档的重新投影另存为研究侧产物，保留新处理时间，原动作、响应、概率及已读
历史均不改写。

最终相关回归 983 项通过；运行集成组 56 项通过，已经包含在大组中，不累加。
独立审查发现并修复结构化正文绕过旧女足/青年队栏目检查的问题；修复后独立
八类正文边界检查以及官方赛果五类反例均通过。

对旧 26 次实际返回，用新的真实处理时刻重投影：3 份目标相关正文（只对应 2 场
比赛）形成 48 条精确引文。原证据 v2 面对相同新 article 输出为 0 条。由这些引文
产生的候选在各独立单响应投影视图中共出现 29 次，去重为 19 个查询字符串，实际
新执行为 0；2 份较长正文达到 64 条总引文上限，保留部分覆盖标记。数量只是接线
诊断，不是独立训练样本数、有效信息量或已实现 VoI 收益。无目标队伍的宣传文字
以及已经过截止时刻才重新解析的正文没有被强行赋予本场证据资格。

总验收 `var/parallel/agent/round188/acceptance.json` 状态 passed。当前代码下的
独立赛果、原时钟语料和正文研究投影均可零网络重算。旧 261 份实际档案及原 R185
语料共 262 个输入文件保持原样；官方采集入口的后续 CLI 接线变更另存审查记录，
首次语料和首次比分核验结果未被覆盖。

统一零网络复验命令：

```powershell
python var/parallel/agent/round188/verify_round188.py
```

官方 API 已接入生产采集 CLI 的显式 `--result-source official-api` 模式。它从
已核验赛事身份构造 URL，冻结到期清单，每场最多一次请求；未到开球后 90 分钟的
比赛直接记 NOT_DUE，不等待。达到该时间只表示可以检查，实际结算仍必须拿到
FINISHED、终场时钟和常规时间比分。原默认 legacy-html 模式保持原行为。

例如下列命令可用于之后一次明确的有界结果采集，本轮没有额外执行它：

```powershell
python -m football_research.data_adapters.verified_fixtures capture-results `
  --identity-bundle var/parallel/agent/round180/identity/identity-bundle.json `
  --identity-archive var/parallel/agent/round180/identity/archive `
  --result-source official-api --route direct --max-http-requests 3 `
  --output var/independent-results/next-verification
```

输出目录必须是新目录。新场次需要使用包含该场次的独立身份 bundle 和原始身份
档案，不能仅替换自由文本队名。核心交付位置：

- `var/parallel/agent/round188/settlement/`：官方原始结果、独立标签及复验入口。
- `var/parallel/agent/round188/corpus/`：逐条训练资格和实际响应监督导出。
- `var/parallel/agent/round188/article-bridge/`：当前版本处理旧正文的独立研究记录。
- `var/parallel/agent/round188/review/`：独立缺口复现与最终审查。

下一阶段仍须按真实时序积累独立比赛：先训练并冻结真实正文预测器，再使用更晚、
身份不重叠的真实响应学习信息价值，最后在再后的比赛确认。不能把两条响应当作
两场比赛，也不能在同一批标签上同时训练预测器和校准器。
