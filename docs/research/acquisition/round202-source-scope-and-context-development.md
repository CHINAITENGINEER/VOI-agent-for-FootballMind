本轮交付于 2026-10-07。目标仍是用户输入比赛，Agent 根据当前可见状态自主发现、估值并选择下一步信息。本轮完成官方来源的有限扩展和原档开发评估入口，同时确认现有 f/g 共享表示的一个核心限制。没有开发前端、降低训练门槛或把构造验证改称真实效果。

## 2. 原档时间开发评估已接通

新增 `football_research/evaluation/optional_context_development.py` 与 `football_research/data_adapters/optional_context_development.py`。公开适配器只接受原始运行目录、原登记计划和结果档案，继续通过已有身份、结果、可见状态与回放网关核验。`optional_context_training.py` 新增只重建语料的入口，开发评估不先拟合全部 A。

评估流程：

1. 分别在训练截止时间和审计时间重建原始结果快照。保留原 observation ID、采集时钟、元数据字节和压缩正文；未来观察不得进入较早快照。
2. 分别重建两份 A 语料。较早已验证的标签可用时间保留；晚到标签不能因较晚重建而进入早期训练。已知标签或可见状态发生冲突则拒绝发布完成报告。
3. 同一物理比赛的别名、重复运行和全部前缀归为同组，用实际决策时间划分。跨训练边界、晚到训练标签、待结算比赛明确排除；不能把重复查询当成独立比赛。
4. 预定每场最早原始运行的初态与最后实际前缀，两张表分别按比赛等权；比较同一个 f 与其实际市场基准或仅训练标签的经验基准，报告 log loss、三分类 Brier、支持和回退。
5. 精确重复检查覆盖正文、标题和链接文字，披露训练/开发重合；没有语义去重或因果增益声明。无支持的回退不能被计为已确认正文收益。

本轮实际调用覆盖 **23 条原始运行、19 场独立比赛、79 次 Agent 返回**，重建得到 **35 个有标签前缀、103 个待定前缀**。其中独立结果仍为 **6 场：主胜0、平局2、客胜4**；无先验域有9场原始比赛，6场至少具有一次正文，但均无独立结果。

开发协议的训练截止为 `2026-10-07T10:51:46.110971Z`，审计截至 `2026-10-07T11:13:15.569034Z`。35 个较早已证明的标签前缀保留原可用时点；6 场进入训练候选，13 场因待结算排除，开发集暂为空。正式训练和开发评估均输出 `not_ready`，`model=null`，开发 `summary=null`。没有模型文件或虚构成绩。

这是检查过既有资料之后制定的 **A 内部回顾性开发评估**，不是事前独立 C。训练执行时钟不回写为历史时间，不宣称新模型曾供原始 Actor 使用。真实结果见 `round202/formal-training/report.json` 和 `round202/development/report.json`。

## 3. 确认了直接影响自主信息选择的表示缺口

独立审查固定 R201 已冻结的构造 f/g、同一段已读正文、时间、缺失先验、来源、预算与下一候选，只改变比赛主体、交换主客身份或替换无关球队。结果：f 和 g 的输入向量完全相同，预测概率和有支持的预期收益也完全相同。

原因是当前编码器虽在审计状态中保存比赛身份，却没有将有序主客主体与正文或候选中的主体关联起来。正文中的球队名称本身不能告诉数值模型该球队在本场的角色。该检查确认的是表示限制，不是实测错误率；完整主客交换也不必严格交换整组胜率，因为主场优势和先验仍可能不对称。

本轮 **发现并复现，没有修复该表示限制**。旧模型继续作为基线。下一项算法工作应只推进一条共享表示：经核验的主客身份与名称别名 → 已读正文/读前候选中的主体关联与未知标记 → 相对本场角色的文本交互 → 同一 f/g 消费。不能仅加比赛 ID，不能为“伤停”“天气”人工指定价值，也不能读取候选尚未取得的正文。

验收须覆盖同一球队在主队、客队、无关主体三种条件下的表示可区分性，未知/歧义主体的明确保留，以及旧原档不回填。再以 A 开发留出验证概率质量及正文增量；可区分表示本身不证明预测更好或查询有益。

诊断原始输入、输出和重现脚本在 `round202/context-audit/identity-report.json`、`identity-inputs.json`、`identity-outputs.json`、`reproduce_identity_invariance.py`。原 R200 语料审查也发现相同可见正文对应不同 raw SHA，仅按页面原始哈希查重会遗漏跨比赛的重复内容。

## 4. 真实数据容量与下一项取舍

当前全部登记为 **A19/B0/C0**。原有6场缺先验 A 加新阶段全部6场，最多提供12场缺先验候选容量；本轮只采集默认七天内的3场，10月17日的另3场保持未来库存。12场只是必要支持下界，仍依赖实际文本、独立结果和三类覆盖。

冠军组尚未曝光的12场应留给 f 冻结后的 B，不继续全部消耗为 A。即使现有范围全部成功，也没有余下独立 C 容量；需要另行预定未来独立来源范围。不能用已曝光 A 重新登记 B/C，也不能把链接数量、正文段落或反复运行当新比赛。

下一最高收益工作为上述主客角色与证据关联的共享表示；赛果按既定时间核验，与实现并行。最早原定检查仍为北京时间10月8日02:10，时间到达本身不构成完场证明。新来源扩展必须围绕独立 B/C 供给，不启动泛化爬虫扩张。
