**FootballMind 项目复盘与后续工作约束，2026-09-27。**

本次复盘响应用户要求：检查项目实际进度，把“开放、不完整、动态变化的信息环境下，Agent 自主决定寻找什么、何时获取、何时停止”作为研究主线。依据是当前源码、平台与 Agent 的累计交付记录，以及第十四、十五轮正式验收。此次交付是复盘文档，未启动下一轮实验。

**当前定位：已有可审计的信息获取研究原型，真实开放信息中的完整自主调查链仍缺关键验证。** 数据、数值规划和执行审计已经有实际成果。最近数轮的主要投入集中于固定历史数据、有限工具和已知分布下的规划验证；这些工作回答了一部分机制问题，对真实开放环境能力的证明仍有限。继续增加同类包装策略、重复回放和测试数量，会让研究重心偏离用户的目标。

代码也说明了当前边界：`football_agent/research_bridge.py::make_backend` 的正式研究入口加载 `FrozenEvidenceEnvironment`；`football_platform/information/live.py` 已实现 spftll 有界刷新，目录为 fixture/history 和 odds；`football_agent/proposer.py` 要求从所给合法目录提出候选；`football_platform/information/prospective_capture.py` 的当前选取依据为 `manual_predeclared`。它们各自有价值，但尚未共同证明 LLM 从当前未知问题出发完成真实开放调查。

最近两轮提供了两类不同证据。第十四轮在反复使用的 200 场历史测试比赛上增加两步规划，实际路径与对应一步策略相同，计入模拟成本后的改进未得到支持。两个信息动作是同一 Understat 响应的历史投影，查询开销为模拟成本。对此应保留负结果，把这批样本视为开发诊断材料，不继续用它们选择“终于胜出”的配置。[第十四轮报告](../parallel/round14/README.md)

第十五轮的价值更明确：在已知生成分布下，第一条信息可以不改变结果概率，却改变下一步该查的工具；Agent 也能在重复或无关信息面前停止。全部 40 种返回组合经过实际工作流。它证明了条件选择机制确实进入执行层，但场景与返回分布均预先设定，新增独立足球比赛、外部请求和真实 LLM 调用均为零。921 项回归通过是上一轮的软件验证记录，不是本轮重跑，也不表示有 921 个开放环境实证。[第十五轮报告](../parallel/round15/README.md)、[正式验收](../../var/parallel/round15/acceptance.json)

最新来源记录同样需要保留准确边界：第九轮有四次直接 HTTP 核实尝试，未取得成功的官方原文响应；新增已核实赛事阶段事实和结构化情境事实均为零，预测与候选收益为空。此前有真实 spftll 获取和市场预测交付，所以“系统从未联网或从未预测”也不符合事实。真正缺少的是**由自主策略选取、由当时实际可取得的开放证据驱动，并对后续行为和决策价值进行验证的完整案例**。[来源第九轮验收](../../var/parallel/collectors/round9/acceptance.json)

**后续研究对象应固定为信息获取过程。** 每次推进都需要回答：当前有什么未知会影响任务？怎样的返回会改变判断或后续查询？到哪里、何时、以什么成本取得它？收到内容之后哪些假设得到支持、受到反驳或仍未知？还值得继续吗？胜平负模型负责提供一个可校准、可评价的下游决策任务。

开放性可以在受控工具边界内逐步建立：通用搜索、读取、结构化 API 等工具类型可以固定，查询问题、检索参数、发现的证据及后续路径由实际状态决定。无需把任意工具生成作为第一阶段条件。反过来，接入很多固定字段来源，也没有自动解决开放信息中的自主决策。

建议下一步围绕五个连续的能力缺口实施，复用现有执行器和数据服务：

1. **任务与知识状态。** 从比赛与决策截止时点建立已知事实、待核实假设、冲突和未知项。区分结果本身的随机性、缺少证据、来源可信程度以及预测/价值模型的误差。一次查询不应以“必须降低胜平负熵”为验收条件。
2. **问题与行动生成。** LLM 提出具体可核实问题，写明答案可能如何影响当前决策或后续查询，再映射到合法工具及参数。保留不同候选的选择依据；避免只在固定伤停/天气/历史菜单中轮流调用。
3. **获取价值与时间。** 价值依赖当前证据、可能返回、后续决策、来源质量、可用时点及成本。已有支持的动作使用数值估计；缺少支持时标记“价值未知/支持不足”，采用预先限定预算的探索或延后策略，并单列依据。未知价值与零价值必须分开；LLM 的文字理由不直接变成精确收益数值。
4. **证据进入认知状态。** 保存原文锚点、来源、观察/发布/可用时间和相关主体；区分原文事实、抽取结论和推理假设；识别转载重复、过期和矛盾。证据可以改变假设、来源选择、调查方向、报告内容或预测，不要求每次都改变数值概率。新领域证据如何改变预测仍需可验证的模型映射。
5. **继续、等待和停止。** 每次工具返回后重新计算或重评。区分信息价值不足、预算耗尽、关键证据尚未公布、检索失败、支持不足及决策截止等原因。遇到信息将稍后公布的情况，等待可以成为候选；出现新证据时是否重开调查也需要明确规则。

目前所谓“预计降低多少误差”往往依赖预测器、返回分布和收益校准器。开放文本的返回空间及其作用并未预先完整给定，精确 VoI 应视为受限条件下的计算结果。后续有研究价值的问题是：怎样在价值估计本身不可靠时选择查询、限制错误更新、控制探索成本，并让实际证据纠正原先的查询预期。现有信息价值接口是起点，普适解决方案尚未得到验证。

用户提出的出线、轮换和防守情境适合检验这条主线。可以把以下关系作为**待调查假设**：已出线之后是否仍有名次目标；有轮换计划是否实际轮换；替补出场是否明显改变实力；平局满足目标是否对应当场保守战术。每一条关系都需要独立证据支持，路径可以跳过、分叉或终止。它们不应变成所有比赛都执行的固定查询顺序。

某队提前出线后仍获胜，单场赛果不足以判定出线信息的价值。相关信息可能在赛前改变了轮换假设，也可能因实际阵容和替补实力而对最终预测影响很小。评价应针对获取前的合理预期、返回后的状态更新及跨案例结果，而不是用已知比分倒推当时是否应该查询。没有可靠证据时，保留不确定性是一种有效输出。

**下一次实施的最小交付应是一条真实、可重放的开放信息调查链。** 选择有真实可获取来源、身份及时点可核验的比赛，任务和预算在运行前固定。初始状态只提供基础事实；真实 LLM 产生待核实问题；工具取得真实返回；证据处理更新状态；Agent 重新决定查询、等待或停止。提供一份逐步记录，回答“当时知道什么、为何查、实际查到什么、如何影响下一步”。单个案例用于打通能力，不用于宣称平均收益优势。

案例的验收关注下面几件事：

- 运行前记录候选问题、依据和选取方式，区分数值价值选择、受限探索与人工安排。
- 调查路径确实由实际返回驱动，不预写一个必须发生的“成功转折”。若实际信息没有改变方向，忠实记录。
- 对正常返回、无新增信息、矛盾、过期、未找到和失败均保留证据与原因。未出现的真实失败类型可用明确标注的故障测试验证处理能力。
- 能正常输出“维持当前预测”“关键事实仍未知”“等待新信息”及对应停止/延后理由。
- 用模型/配置版本、输入快照和工具返回支持回放；数学假设分支不计作实际取得的证据。

随后开展一组事先定义选取规则的真实案例，包含比赛情境差异与来源失败。对照至少覆盖固定查询流程、LLM 自行选取工具、加入价值约束的 Agent；资源预算、初始信息和下游预测接口保持可比。多策略运行应处理来源内容随时间变化和共享缓存成本，明确哪些是实时观测、哪些是固定快照上的重放。

评价分为两个层面：

| 层面 | 应记录的结果 | 解释范围 |
|---|---|---|
| 过程能力 | 问题是否有证据依据；答案可追溯；重复/失效查询；返回后的改问/换源/停止；矛盾处理；真实请求、时延和费用；未知信息是否如实保留 | 人工核验标准提前固定。查询多、路径多变、概率变化大都不自动代表质量高 |
| 下游价值 | 固定任务下的预测校准、适当评分、是否延后决策及其覆盖率、实际获取成本、跨案例差异和失败 | 使用独立样本和事先确定的比较。过程运行成功与净收益改善分开报告 |

“信息价值”也不应由 LLM 的自我评分充当真值。真实环境下未获取信息的反事实通常未被观测；少量事后审计或实验性采集应与 Agent 的在线轨迹、实际成本分开标注。受控机制实验继续承担可观测反事实的验证作用，真实案例承担开放来源和实际决策证据的验证作用。

**对后续任务的约束：** 暂停把同一历史集上的阈值、融合权重、规划包装和重复回放作为主要进展；不按数据源数、模型数、Agent 数、测试数评价研究推进；保留固定基线和必要回归，但新工作应明确补足一项开放信息能力，或回答一个已观察到的决策失效问题。确认性实证另用独立数据，既有反复研究的历史集合继续标为开发诊断集。

当前最需要的下一步是完成语义问题生成、真实获取、证据更新和动态重规划的连接。可在接口明确后并行处理 Agent 与证据接入，暂时没有增加算法线程数量的必要。现有能力值得保留，后续验收以“Agent 在真实未知信息面前做出了什么有依据的获取决策”为主。
