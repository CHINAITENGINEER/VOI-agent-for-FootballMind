## 结论

FootballMind 已经具备一个很强的**开放信息 Agent 工程底座**：用户只给比赛，系统
可以维护公开状态、提出候选信息、按预算执行、处理失败/迟到/冲突、重新规划、停止，
并把每个动作写入可回放的 Episode。Round170 又把 `prediction_before` 与
`prediction_after` 的位置和截止时间固定下来。

但它还不是一个可以完整提交的 AIC 算法项目。当前最重要的缺口不是更多采集器或更
复杂模型，而是下面这条可验证链路尚未在真实历史数据上闭合：

> 同一场比赛、同一预测截止时间、同一公开初态和同一查询预算下，Agent 选择一条
> 信息；返回进入公开状态；后验概率发生可解释更新；Agent 依据更新重新选择或停止；
> 最后用独立赛果评估这条路径的损失、成本和停止质量。

截至本文件建立时，`tests/agent` 为 3170 项通过，`tests/demo` 为 53 项通过，合计
3223 项；这些结果验证的是边界、持久化和回放契约。项目仍没有新增真实来源请求、
实时模型调用、独立比赛金标准，因而不能声称足球预测准确率、真实数值 VoI 或收益已
经提升。

## 核心算法必须怎样定义

现有 interval/state-bound 估计器适合做安全门控，但它使用的是历史观测风险下降区间，
不能自动等同于“当前比赛的数学 VoI”。下一阶段把两者分开：

设当前公开状态为 (s_t)，赛果为 (Y)，当前预测为

\[
p_t(y)=P(Y=y\mid s_t),\qquad y\in\{主胜,平,客胜\}.
\]

候选信息动作 (a) 的可能返回为 (z)，响应模型为

\[
q(z\mid s_t,a),\qquad
p_{t+1}(y\mid z,a).
\]

在选定的决策损失 (L) 下，候选动作的期望信息价值是

\[
EVSI(a\mid s_t)=R(p_t)-\sum_z q(z\mid s_t,a)R(p_{t+1}(\cdot\mid z,a)),
\]

其中 (R) 是当前概率决策的期望损失。真正的净价值还必须扣除成本、延迟和来源
可靠性折扣：

\[
NetVOI=EVSI-\lambda C(a)-\mu D(a)-\rho(1-Q(a)).
\]

本轮新增的 `football_research.acquisition.expected_voi` 只实现这一个**严格的一步
契约**：显式响应分布、显式后验分支、分支混合必须与当前先验一致；不一致时返回
`INELIGIBLE`，不偷偷归一化。所有候选的 `NetVOI` 都已计算且不为正时，才允许产生
“有限候选集上的自主停止”证书；有候选价值未知时只能 `defer`，不能把未知当零价值。

这一步仍然是模型期望值，不是比赛真实收益。真实收益必须由独立赛果 sidecar 和
paired replay 计算。LLM 可以生成候选问题、理解返回、解释证据和提出新候选，但不能
直接把一句“我觉得伤停重要”写成数值 VoI；数值门由可审计的 predictor、response
model、cost model 和 stop rule 共同决定。

## 足球情境变量如何进入，而不是变成硬规则

“已提前出线”“打平即可第一”“可能轮换”“需要净胜球”都很适合做**情境条件**，但
不能写成 `qualified => weaker` 这样的固定因果规则。它们应作为带来源和 cutoff 的
公开状态字段：

- `qualification_state`
- `points_needed`
- `draw_suffices`
- `goal_difference_constraint`
- `competition_priority`
- `rotation_probability`
- `lineup_strength_delta`
- `tactical_risk_preference`

日本对泰国的例子说明“提前出线”并不总能改变首发和比赛强度；中国对阿联酋的例子可
以作为“平局满足目标、战术风险偏好可能改变”的压力场景。两者都只能作为待验证的
查询假设：Agent 先评估这些字段是否未知、是否可能改变后验、是否值得付出成本，再
决定查询首发、赛制目标、战术布局或直接停止。单场赛果不能倒推一次查询有价值。

## 参赛版必须补齐的六个缺口

### 1. 真实历史 episode 集

先做 300 场可重放 episode 作为纵向集成门，再扩展到 800–1200 场用于校准和留出测试。
每场必须冻结：比赛身份、开球时间、预测 cutoff、当时可见的基础事实、候选工具菜单、
每个工具的来源/观察/可用时间、返回正文摘要、真实资源成本和独立赛果。至少覆盖三
类赛事、普通比赛、提前出线、平局即可晋级、轮换/伤停不确定、来源失败/冲突等情境。

### 2. 一个透明且固定的概率基线

主基线固定为 Elo + 时间衰减状态 + Dixon–Coles/Poisson；可再报告 LightGBM，但不能
用模型堆叠掩盖数据泄漏。所有预测都输出三分类概率，报告 log loss、Brier、ECE/可靠性
图和时间滚动结果。预测器必须通过 `prediction_adapter` 与显式 state projector 接入
运行时，不能使用结果字段或 cutoff 之后的内容。

### 3. 可校准的 response model

对每类查询估计“可能返回什么”以及“返回何时可用”：首发/伤停、赛制目标、球队状态、
战术/轮换、赔率变化、天气。历史支持不足时输出 `unknown/defer`，不要用 LLM 自评补
齐。response model 的版本、训练截止和来源版本必须写进 Episode。

### 4. 成对基线和消融

在同一初态、同一候选菜单、同一预算、同一 cutoff 下至少比较：

1. `stop-only`：不查询；
2. `fixed-order`：预先固定查询顺序；
3. `full-query`：预算内全部查询；
4. `random`：随机合法查询；
5. `LLM-heuristic`：同一个 LLM 只按文字判断调用；
6. `FootballMind-VoI`：数值门控、证据状态、重规划和停止；
7. `oracle`：只作上界，不当作可部署方法。

主指标不是调用数量，而是质量—成本曲线：最终 log loss/Brier、校准、查询次数/延迟/
费用、信息效率、停止正确率、错误自信率和失败恢复。所有独立比赛按时间滚动划分，
重复运行不增加独立样本数。

### 5. 一个真正的端到端入口

用户只输入比赛。系统必须自动完成：身份确认 → 当前后验 → 候选信息生成 → 计算/估计
价值 → 调用一个或多个来源 → 证据准入 → 后验更新 → 重新选择/等待/停止 → 输出报告。
报告显示：before/after 概率、每个候选的净价值组成、实际成本、证据来源与时间、跳过
原因、停止证书和未知项。不能再把“请告诉我你还想查什么”放在主流程中。

### 6. 参赛可复现和失败案例

提供一条命令生成固定版本的实验表；冻结代码、配置、模型、提示词、数据 manifest 和
随机种子。准备三个不剪辑的案例：

- 伤停/首发不确定，Agent 查询后改变概率；
- 已出线但实际阵容没有明显下降，Agent 在证据不足或低价值时停止；
- 平局满足晋级目标，战术/目标信息改变查询路径或最终风险解释。

同时展示来源冲突、空返回、迟到、预算耗尽和错误身份。失败案例比单场漂亮预测更能
证明系统理解开放环境。

| C：运行时接线 | 真实 baseline + projector 接入 `autonomous_runtime_loop`，跑通一场真实历史 episode | before/after 概率、证据准入、重规划和停止均有记录 |
| D：评估与答辩 | 七组策略、时间滚动 paired replay、指标/置信区间/失败分析、三分钟 Demo | 所有主张都有对应表格、轨迹和限制 |

A/B/C 可以立即并行；D 的协议和脚本现在就能准备，但最终结果必须等 A/B/C 的真实
episode 到位后再冻结。每个工作包以产物验收，不以“又完成多少轮”验收。

## AIC 最终项目版本

### 建议标题

**FootballMind：开放动态信息环境下基于信息价值的自主概率决策 Agent**

### 一句话科学问题

在信息来源开放、质量异构、持续变化且获取有成本的环境中，Agent 能否根据当前后验
不确定性选择下一条最值得获取的信息，并在预期净价值不再为正时自主停止，同时保持
概率校准和全过程可审计？

### 答辩叙事

先展示普通模型的问题：人工固定输入，所有比赛查询同一清单；然后给出两个情境：提前
出线不一定轮换，打平即可晋级可能改变战术。系统只看到一场比赛，先给出初始后验，
再列出候选信息和价值分解，自动查询最有可能改变决策的来源，收到返回后更新后验，
最后显示“继续、等待或停止”的数学理由。用配对实验说明它不是因为“查得更多”而好，
而是用较少或相同成本获得更低的决策损失。

## 文献依据

- Shachter, *Efficient Value of Information Computation*：将 VoI 作为观察不确定性后
  改变决策价值的差异，适合作为数值定义起点：
  https://arxiv.org/abs/1301.6739v1
- Da Costa et al., *Active inference, Bayesian optimal design, and expected utility*：
  说明信息增益、期望效用和目标导向的信息获取并不等价，支持 FootballMind 不能只用
  熵下降排序：
  https://arxiv.org/abs/2110.04074
- Soleymani et al., *Foundations of Value of Information*：强调信息是否值得交换要
  放在任务代价和控制目标中判断，支持把延迟和成本写入净价值：
  https://arxiv.org/abs/2403.11927v1
- Gneiting & Raftery, *Strictly Proper Scoring Rules, Prediction, and Estimation*：
  为 log loss/Brier 等概率预测评价提供理论依据：
  https://doi.org/10.1198/016214506000001437
- Dixon & Coles, *Modelling Association Football Scores*：为透明的足球比分概率基线
  提供可复核起点：
  https://doi.org/10.1111/1467-9876.00065

## 本阶段的边界

`expected_voi.py` 和它的测试只证明了严格的数学输入/输出契约，不证明任何真实足球
收益。只有当 response model、baseline predictor、independent gold 和 paired replay
齐备后，项目才可以把“VoI 策略优于固定查询”写成实验结论；在此之前只能说完成了
研究接口和机制验证。
