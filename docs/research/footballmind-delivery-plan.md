## 1 核心问题与交付

研究问题：信息不完整、候选持续出现、获取有成本且来源可能无法回答时，Agent 如何决定下一步寻找什么、是否值得获取，以及何时停止？

运行链路：

    比赛身份与已有基准分布
      → 来源发现与当前真实内容
      → 语义模型自主提出未知、查询与有限情景
      → 数学模块计算条件 VoI、成本与模型敏感性
      → 选择查询或结束
      → 真实获取、正文准入与引文分类
      → 同一联合模型更新情景权重
      → 扩展候选、重新估值与报告

最终交付一个可执行案例、完整归档与中文报告、运行及数学回放命令，以及少量直接检验机制的对照。用户不必先指定“查伤病还是天气”。比赛身份、来源入口、工具能力与预算可以预配置，具体未知、条件价值及查询顺序不能预写。

本期主张是：**将语义模型生成的明确概率假设转为一致联合分布，由数学风险决策模块控制自主信息获取。** 假设未经实证校准；机制完成不等于预测提升、平均节费或开放世界完备停止。

### 0. 单场输入边界（当前新增底座）

用户只提交比赛身份或“主队 vs 客队”文本。系统先生成带摘要的规范请求和
actor-visible 初始状态：已知的球队／赛事／时间与显式未知的信息需求分开保存，
候选目录只描述可用能力、依赖和证据类型，不预设价值、费用或固定查询顺序。
缺少开球时间时进入 `kickoff_unresolved` 的待解析状态，由来源解析补齐；系统不
向用户追问“想研究伤病还是天气”。请求契约拒绝比分、赛果、赢家和损失等结果泄漏，
并把 `policy_mode=conditional_semantic_voi_untrained_g` 固化在运行元数据中。
入口是 `tools/prepare_footballmind_match.py`，它只准备底层状态，不声称已经完成
身份核验、概率预测或信息充分性证明。

若要把准备态送入完整语义运行器，新增的
`tools/materialize_footballmind_case.py` 要求显式提供同一场比赛的来源 profile、
`bootstrap_url` 和三分类结构化基线；它会核对主客身份、时间边界、允许域名和概率
归一性。缺少这些材料时返回 `case_not_ready`，不会复制 Arsenal–Leeds 基线，也不会
生成均匀概率。运行器从案例 profile 或显式 `--bootstrap-url` 读取启动入口，不再把
任何特定俱乐部 URL 写死在控制器里。

当前在等待带时间戳信息流期间，执行顺序固定为：

1. **输入与状态底座（已落地）**：`autonomous_match_contract.py` 将一场比赛规范化，
   固化结果隔离、时点边界、未知字段和不向用户索要研究范围的契约。
2. **能力目录与状态绑定（已落地第一版）**：每个信息需求只声明可用来源能力、依赖
   和证据类型；`bind_source_capabilities()` 将来源健康映射为
   `available/unknown/unavailable/stale/conflicting`，但价值、成本与优先级保留为空，
   交给当前状态下的 VoI 求解。
3. **运行桥接（已完成第一版）**：match-only `ExperienceService` 会把初始状态和能力
   目录放进每轮 `public_state`；模型继续自主提出问题，且不会因为目录存在就得到固定
   顺序。原生比赛 ID 或无法立即解析的文本保留为 `resolve_fixture_identity`，不退回让
   用户选问题。语义情景 runtime 的真实来源、概率假设和停止报告继续沿用同一份策略
   标识；`semantic_match_adapter.py` 会在注册案例中核对主客身份、显式赛事／时间／比赛 ID 后将同一状态绑定到
   数学 VoI runtime。命令可通过 `tools/run_footballmind_semantic_case.py --match`
   显式启用，换场次会被拒绝，不会把旧案例的基准偷偷套到新比赛。
4. **机制验收（已落地）**：用日本—泰国式“已出线但未必轮换”、中国—阿联酋式“平局
   足够但战术需另证”、关键伤停、天气低价值和来源冲突五类离线情景，验证候选依赖、
   不得由背景事实直接推出阵容／战术、查询后重规划和停止边界。可执行验收入口为
   `tools/check_footballmind_autonomous_mechanism.py`，当前 8 个场景共 67 项检查全部通过。
5. **人工体验前封版**：只检查一场比赛输入能否完整走完“解析—候选—查询—更新—停止—
   报告”，修复阻断主线的问题。经验 `g` 仍保持接口就绪但不参与本期动作选择。

## 3 当前技术主线

### 状态与自主信息需求

H 包含比赛身份、基准分布、截止时间、已取得正文与发布时间、实际观察、已尝试事实组及预算。未读取的目标正文、未来赛果和训练标签不进入当前输入。

CandidateDiscoveryProtocol 允许 Agent 根据 H 自主提出0—3条搜索 query 及信息需求；真实已读来源中的新闻链接也进入候选。提出查询不等于执行。runtime 绑定实际工具能力后交给数学模块。首次菜单最多8项，记录上限与遗漏项；停止不覆盖未纳入菜单的候选。

- read_url：读取已知入口或已发现 URL，声明一次 HTTP 成本。
- search_then_read：搜索后读取返回顺序中首个允许的新闻 URL，声明至多两次 HTTP；空搜索实际可能只花一次。摘要和标题不作正文证据。

ProposalProtocol 必须对全部传入候选建模，不能通过省略难估项决定选择。无法区分情景的候选可有相同条件似然。新链接由 ActionExtensionProtocol 扩展动作，保持原情景、先验、结果分布和旧动作不变，核对既有证据的后验保持。

### 一致联合模型与信息价值

语义模型提出2—6个有限情景 theta、先验 pi、情景下胜平负分布及支持／反对／无答案似然。互斥、覆盖和因果解释是明确建模假设；程序验证概率有限、严格正、归一、情景及动作身份，不能证明语义充分性。

    q(theta, y, z_a | H) = pi_H(theta) q(y | theta) q(z_a | theta, a, H)

通过固定先验、共享结果 logit 偏移的联合 I 投影，使初始胜平负边际等于已有基准 p0。前后预测来自同一联合对象；这是数学一致性，不是统计校准。

对数损失下精确求和：

    VoI_q(a | H) = entropy_q(Y | H)
                  - sum_z q(z | H,a) entropy_q(Y | H,z,a)
    net_q(a | H) = VoI_q(a | H) - lambda × declared_request_cost(a)

预声明污染模型集 [0, 0.25, 0.5]，将观察似然与不区分情景的边际混合。每个模型独立更新和积分，选择净价值集合下界最高、为正且预算可行的候选。下界是固定集合包络，不是置信区间，不能覆盖所有遗漏情景、来源依赖或失配。

默认规划深度仍为一步，保证既有真实运行与回放兼容；运行时现在可显式配置
`planning_horizon=2`，在同一冻结情景和可见菜单内使用有限两步前视：首个查询
即使即时 EVSI 低于成本，只要某些返回分支后的一个最优后续查询使两步净值为正，
就可以被选择。当前新版本使用 `planning_policy=shared_observation_continuation_v1`：
每个返回分支只选择一项所有污染模型共享的稳健续动作，随后计算同一策略在各模型中的
净值下包络；这是可执行的逐分支策略，不声称全局 max-min 策略树最优。不能将各模型各自
最优的不同续动作相加，再当作可实施价值。第二步同时遵守已尝试动作、同事实组和整数
请求预算，即使损失成本为零也不例外。两步菜单允许同事实组的不同来源，有信息返回后
关闭该组，无答案能否换来源沿用冻结的组策略；不把转载当作独立证据。候选再发现
仍发生在真实返回之后，不能被反事实预取。该能力是声明模型内的有限机制，不是经验
`g`、全局开放世界停止证书或任意长度策略；扩展动作的似然仍只条件于已经发生的真实历史。
无新 marker 的旧 manifest 保留原计算用于历史精确回放；研究比较先验证旧回放，再在同一
冻结状态显式使用新规划器重算 h1/h2。两次不同 LLM 提案不构成规划深度的控制实验。

### 实际返回与依赖

- 正文必须来自实际返回，通过同页解析、内容角色及时间准入；分类只看本次取得的合格正文和固定问题，提供连续原文引文。
- supports/refutes 且 match_specific 才能作为有信息观察更新。
- 失败、无正文、无法回答、一般球队背景或作用域不明都记为 no_answer。
- no_answer 的似然跨全部情景相同，消耗资源并关闭已尝试事实组，但不改变比赛信念。
- 标题、国家队出勤、旧照片和一般球队新闻不能自动证明本场阵容、伤停、轮换或战术。
- 同事实、重复来源或转载共用 observation group，每组最多尝试一次；不同组的残余依赖仍是限制。

引文字符串匹配只证明这些字出现在正文中。语义分类、真实含义、时间与本场适用性仍要人工审阅，不能写成真实性保证。

### 成本与停止

主运行每 HTTP 请求损失等价成本固定0.001 nats，总预算6次。入口发现属于声明的启动开销，计入请求，不冒充 VoI 入选。LLM 请求、时延和 token 单列，尚未纳入决策目标；货币费用未知不能视为零。

停止区分：声明模型与菜单内没有正净价值下界、没有未尝试事实组、请求不足、截止时间、语义调用预算及工具／协议失败。任何结束都不证明开放世界没有更多有用信息。

不得事后调成本来替换主实验结论。另存明确标识的成本敏感性或零成本机制演练，只用于相应条件下的机制检查。

主案例沿用现有导出中的 Arsenal–Leeds 记录，基准来自已有结构化历史重建模型。运行 metadata 标记场次身份为单一导出、结构化预测为外推；不改写成已独立核验的实时赛程。

既有26场／62篇正文／112条背景标题、A15/B5/C6资料保留：

- A 段整场留一中，纯基率 log loss 1.090284，原正则化10的文本模型1.090782，预声明网格没有胜出。
- 冻结胜出的基率模型后，46个 B 段正文增益全零。零来自模型不使用正文，不代表信息实际无价值。
- 原收益模型接近常数；状态枚举与数值微变不能证明条件选择有效。
- 相对排序有有限信号，但独立样本少，不能证明稳健收益，也不能用相对正分替代绝对停止。

这些是经验路线对照，不再是当前路线的训练前置。历史重建、当时实际归档、当前获取、模型假设和构造测试分别标记。旧有限情景 synthetic 产物不能改称真实学习或已观察效果。

### 三种证据必须分开

1. **主真实运行 live-01，正常成本。** 1次入口 HTTP、2次真实语义调用。Agent 提出2条查询，结合6条已见新闻链接形成8个数值候选，全部没有正净价值下界，未执行正文查询。初终概率均为主胜62.031458%、平25.392844%、客胜12.575698%。不是全 UNKNOWN 探索，但也没有正文更新。
2. **独立 mechanism-01，零成本机制演练。** 配置为 zero_loss_cost_mechanism_exercise_not_policy_success。6次 HTTP，包括1次入口、2次失败搜索、3次正文读取，实际正文合计3676字符；6次真实语义调用、一次候选扩展、6个数学决策周期。5次动作观察均为 no_answer，后三次分类为 team_context。请求预算耗尽，初终概率在浮点误差内保持一致。证明真实获取、返回处理、扩展和重估链路执行，不能证明主成本下收益或本场有效证据。
3. **构造机制检查。** 人工设定情景与返回检验支持／反对后的数学更新、排序、重复、无答案及预算边界。明确是单元／集成测试，不作为真实赛前效果案例。

两条真实轨迹分别完成1／6周期的零 HTTP、零 LLM 精确数学回放。回放重算保存的模型和观察，不重新作语义分类。原始文件位于 var/submission/p6-semantic-scenario/，主运行和机制演练不能相互覆盖或混写。

### 剩余最小工作，按收益排序

1. **收敛机制对照。** 本轮已固定 live-01 的真实 proposal，在单位成本0、0.0001、0.001、0.01下重算名义及稳健价值，结果保存于 `live-01-sensitivity/`，前两者查询、后两者停止。它是事后模型敏感性，不用于反选成本或改写主运行。后续只补尚缺的必要消融；只有共同实际返回存在时才能比较实际结果，否则只报告模型条件动作差别，不填造反事实正文或收益。重点保留本次真实 no_answer、后验保持与重估证据。
2. **人工审阅实际问题、情景和引文。** 检查未知是否切题、情景是否重叠或遗漏重要解释、影响幅度和似然是否过强、正文是否能回答本场问题。机制03已经给出一条正文被判为 `supports + match_specific` 后更新的可审阅轨迹；它仍是零成本历史重建，不是准确率证据。此项不需要等最终赛果或扩充联赛。
3. **统一参赛材料。** 将自主问题生成、数学价值控制、真实获取、敏感性、负结果和限制写入同一主叙述；代码、命令、公式和报告指向相同产物。官方模板另有要求再适配，不阻塞算法工作。
4. **历史机制案例已完成。** `var/submission/p7-historical-semantic/` 记录了按元数据预选的 Leeds–Fulham 历史正文面板、正常成本停止、零成本正文回放及同面板策略对照。它只作为历史重建机制材料，不替代独立前瞻效果评估。
5. **进入预留人工窗口。** 10月20日至22日只检验“用户给比赛后 Agent 是否自主提出并选择信息、返回后是否改变下一步”；23日至24日只修身份、证据准入、重复计数、数学与报告不一致、无法停止等核心问题；不增加前端、联赛、一般产品能力或长周期训练。

### 10月8日至25日新增时间的投入顺序

1. **候选再发现（最高优先级）。** 允许 Agent 在一次真实返回后，基于当前观察重新提出有限的新信息需求；新动作必须沿用冻结情景、先验和已有证据，由同一 VoI 求解器决定是否执行。参赛新运行显式配置最多一次再发现；旧冻结回放和未配置的底层 runtime 默认仍为零次，保证历史产物兼容。严格限制语义调用和请求预算。
2. **查询命题与情景绑定。** 新运行已启用 `semantic-directional-observation-v1`：每个动作由同一 VoI 求解器选择，且 proposal／动态扩展同时冻结 `direction_contract`，明确该动作的支持与反驳方向。正文只有在明确回答本场问题、给出主客队方向性影响、并命中该合同方向时，才保留 `supports/refutes` 进入后验；相反方向、混合但未被命题允许、或仅有“存在伤停/康复/训练信息”而没有本场影响方向时，运行时将其降为 `no_answer`。旧历史产物继续使用旧协议回放，避免改写冻结证据。
3. **风险分支诊断。** 在不改变动作选择规则的前提下报告 `P(risk_after > risk_before)`、期望风险变化和触发分支，区分“某个返回分支使熵上升”和“期望获取价值为正”。
4. **经验 `g` 只做可退出研究。** 不把历史常数零基线接回主链；若有余力，仅按独立比赛和时间切分做一次冻结可行性检查，两个独立时间折不能稳定超过常数基线就停止，不为产生正结果继续调数据或成本。

## 6 并行、范围与更新规则

总控负责唯一计划、主案例与统一交付；数学、语义／证据、报告和必要核验按文件归属并行。无需新增大型数据平台、通用多 Agent 编排或重复审计服务。

保留必要来源、时间、未读内容隔离、赛果隔离、预算及回放，避免将这些底座独立膨胀为长期任务。每轮合并实现、相关验证、实际结果和交接，不再拆成大量零碎轮次。

现有授权覆盖公开来源、必要实现、并行及本语义情景路线，无需重复请求路线许可。付费承诺、无法确定的任务范围、需要用户提供的赛事要求或无法保留人工窗口时再明确提出。

每次汇报说明当前单场自主选择哪项能力真实可用、哪些只是实现或假设、实际发生了什么、仍不能声称什么，以及下一项最高收益工作。测试数、文件数和 Round 编号不能代替进度。

最终验收句：**面对这一场比赛的开放信息与不确定性，Agent 自主提出需要寻找的信息，数学模块在明确假设下决定是否获取，真实返回后重新判断，并给出范围可核查的结束依据。**
