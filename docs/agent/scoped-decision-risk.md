# 决策损失进入信息获取选择

`scoped-inquiry-decision-risk-v1` 把明确的终止决策损失接入现有调查工作流。LLM 继续提出问题、提取来源表述和生成参数化查询；数值模块只比较具有声明返回模型的候选。原始 LLM 提案、程序选择、实际请求及实际返回分别保存。

适用入口是 `evidence-state-inquiry-v1`。原调查协议默认行为保持不变；普通开放文本的数值价值仍是未知。

## 数学目标

在已获取证据对应的后验状态 $b$ 下，终止决策的风险为：

$$R(b)=\min_d\sum_y P(y\mid b)L(d,y).$$

这里 $d$ 可以是报告“是”、报告“否”或“保留未知”；代价由任务明确声明。新模型不要求将所有任务写成胜平负概率预测。

对查询 $q$，遍历每一种可能返回 $z$，包括失败：

$$\operatorname{EVSI}(q\mid b)=R(b)-\sum_z P(z\mid b,q)R(b_{q,z}),$$

$$\operatorname{NetValue}(q\mid b)=\operatorname{EVSI}(q\mid b)-c(q).$$

选择器采用一步视野。在有效、可支付且已提出的已建模候选中，选择期望终止损失加获取代价最小且净价值为正的查询。获取后只用实际收到的文档或失败状态更新后验，再重新计算。

信息熵下降不必降低决策损失。例如一个弱信号把概率从 0.5 改到 0.6，但在给定误判与暂缓损失下，两种情况都应保留未知，此次信息的决策价值可以为零。测试同时检查互信息大于零、决策 EVSI 等于零。

这是标准有限决策模型的工程接入，公式本身不作为原创算法成果。尚待研究的是开放查询的返回模型、语义映射及其估计误差如何支持可靠的行动选择。

## 模型、来源与时间范围

- `FiniteDecisionLossModel` 复用有限观测模型，加入具名决策和损失矩阵。成本以同一种终止损失单位声明；没有把请求次数、百分数或美元直接相减。
- `DecisionRiskSelector` 绑定任务 ID、确切 HTTPS 地址、不可变假设定义、证据类型、成功返回的完整文本及失败标记。
- 当前完整文本匹配只适合构造环境或有固定契约的离散接口。它不解决任意新闻正文的语义解析、可信度或似然估计。
- 任一已获取文档没有返回模型、正文不匹配、返回已过截止、重复一遍性动作或后验与观测历史不符，都使该状态退出数值支持。后续行动可以继续受限探索，数值收益为空。
- 来源相依关系需要进入联合潜变量。在构造实验中，两个核对入口共享同一个可用性变量；第一次失败后，第二入口仍可调用，但其信息价值降为零。这个结论依赖声明的相依模型，不能外推为所有同站点请求都会失败。
- 当前动作是一次性的静态快照。`refresh_k` 表示与已读旧报告不同的注册快照；没有实现连续时间随机变化的通用刷新模型。
- 继承文档更新当前信念，保留原观察时间；本次损失预算仅计本次执行的获取代价。来源失败也会产生本次获取代价。

## 停止与未知候选

停止证书明确限定为：**声明的有限模型、当前预算、一步视野内**。`global_open_world_stop_proven` 恒为 `false`。

未建模候选的价值为未知，绝不赋零。若已建模候选都没有正净价值而仍有未建模候选，不签发模型停止证书。若注册模型还有值得获取的信息但 LLM 没提出对应的有效候选，记录提案缺口并暂缓。请求预算用尽与价值耗尽分开。

即使注册模型的一步净价值都不为正，仍可能存在多步互补信息，也可能存在尚未发现的开放查询。因此该证书不意味着全局最优停止。

有剩余请求额度时也可以停止，同时让部分终止结论保持 `defer`；风险为零不是停止的必要条件。

## 接入与重放

`InquiryWorkflow(..., protocol=EvidenceStateProtocol(), selector=selector)` 为程序接口。命令行配置可增加 `decision_selector: selector.configuration()`，并使用 `inquiry_protocol: evidence-state-inquiry-v1`；普通配置不需要这个字段。

```powershell
python -m football_agent.inquiry_cli --config path/to/config.json --root path/to/new-run
python -m football_agent.inquiry_verify --root path/to/new-run --run-id RUN_ID --output path/to/proof.json
```

每条数值决策保存 `llm_proposal`、候选价值、观测映射、模型哈希、成本单位、终止决策及停止范围。核验器从冻结配置与实际文档重算数值选择，并检查被执行的候选和请求参数确实对应程序选择。已有 `return_reviews` 比較的是前瞻计划与下一次 **LLM 提案**，不是数学选择器的执行或效用标签。

构造实验入口：

```powershell
python -m football_agent.decision_risk_experiment --root var/parallel/agent/round21/NEW_EXPERIMENT_ROOT
python -m pytest tests/agent/test_inquiry_value.py --import-mode=importlib -q
```

实验保存源文件快照、事前模型、私有环境返回、真实 CLI 收据、构造传输归档和核验记录。环境返回不会进入模型输入，只有实际执行后获得的文档进入后验。两个预登记案例的先验、初始相反报告和潜在工具返回相同，只改变 K 问题的误判损失。每例最多五次模型调用、三次构造传输；异常保留，不对结果挑选重试。

真实 CLI 调用证明语言模型参与了候选生成；构造传输证明完整执行闭环。两者都不是新增足球样本，也不构成已校准的策略收益估计。
