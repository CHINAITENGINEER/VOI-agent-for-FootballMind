**查询返回预期与后续行动：`return-forecast-inquiry-v1`。**

这个可选协议让 Agent 在查询前说明“得到不同返回后准备怎么做”，随后用实际获得的证据和下一次行动提议检查原计划。它继承前提状态、带引文的适用关系、证据复用和有限预算执行，补上可被实际返回检验的观察与行动预期。当前查询选择仍是 `llm_bounded_exploration`，数值信息价值尚未接入。

启用配置为 `inquiry_protocol: return-forecast-inquiry-v1`。入口与此前相同：

```powershell
python -m football_agent.inquiry_cli --config TASK_JSON --root NEW_RUN_DIRECTORY
python -m football_agent.inquiry_verify --root RUN_DIRECTORY --run-id RUN_ID --output VERIFICATION_JSON
```

已保存的英格兰—西班牙任务配置有固定的真实赛前截止时间。截止后应离线重放原运行；研究新的比赛应新建任务和来源记录，而非修改旧运行的时间。

**查询前。** 每个候选保留 `inquiry_intent`，并增加 `return_model.branches`。分支预测由模型提出；程序检查结构、已知假设与声明的证据类型，不把模型的合理性判断视为经过校准的预测。

| 字段 | 含义 |
|---|---|
| `outcome` | 提取层的返回类别，必须覆盖下列七类且各出现一次 |
| `missing_after` | 本次查询各目标假设在返回处理后的剩余前提类型；只使用已声明的前提 |
| `next_action.kind` | `query / reflect / stop / wait / defer / reassess` |
| `next_action.target_hypothesis_ids` | 再查询时针对的已有假设；其他行动为空 |
| `next_action.evidence_types` | 再查询时寻找的证据类型；其他行动为空 |
| `next_action.reason` | 这个返回为何导致这一后续提议 |

七类分别是 `source_support`、`source_challenge`、`mixed_source_signals`、`context_only`、`discovery`、`no_answer`、`failure`。前四类来自已有单文档贡献投影；`discovery` 表示有此前未见的允许域名链接但没有上述归属的证据；`no_answer` 包含空结果和未提取到可用证据或新链接；`failure` 包含请求失败或内容不可用。失败先于证据分类处理，空搜索结果不视为命题遭到反驳。

这些类别是工具返回和提取的观测标签，并非完整世界状态划分。导航链接也可能触发 `discovery`，它不代表有用信息；`no_answer` 也不保证原文实际没有线索，提取可能遗漏。有效规则只作为推理前提，不会因为命中 `source_support` 就自动补齐所有输入。相同类别下仍可能有不同的剩余缺口，所以粗粒度分支预测本身也可能失败。

选中候选后，执行器在 HTTP 请求之前把分支计划、当时已知链接和前提状态写入 `inquiry_acquisition_intent`。原有事件链固定这一版本，不使用未来返回重写查询前预期。

**查询后。** 下一次有效模型回复可以提交来源表述、适用关系和新行动。程序据此计算实际分支与前提状态，产生 `return_reviews`：

- `gap_forecast_match` 比较计划中的缺口与处理返回后的联合证据状态。
- `continuation_match` 比较行动类型、目标假设集合及证据类型集合，忽略文本理由和集合顺序。它不比较具体 URL、查询字符串或返回内容。
- `reassess` 表示当时没有给出可评分的后续行动；比较结果为 `null`，不计为预测正确。
- 状态分别保留 `matched_declared_plan`、`deviation_from_declared_plan` 或 `open_continuation_not_scored`。偏差不会把新行动退回原计划，也不会自动否决查询。
- `expected_gain` 和 `realized_decision_utility` 均为空。计划吻合不等于信息有价值；合理的新发现也可能使原计划失效。

这里比较的是**下一步提议**。该提议之后仍会经过预算、截止时间和重复请求检查；如果要报告实际执行，应另核对后续获取事件。预算外的查询提议不应被写成执行成功。处理返回时还可能整理既有文档，故缺口变化属于联合状态变化，不是这一次 HTTP 的独立因果收益。

候选反馈另外报告成功返回下有多少种不同的后续提议和缺口模式。`no_answer / failure` 不参与“成功分支是否不同”的计算。所有成功分支提出相同行动，只能提示检查其信息用途；不能据此判定 VoI 为零，因为终局判断、较后行动及尚未建模的差别仍可能改变。

**研究用途。** 现在可以保留查询前状态、候选和选中计划、真实请求、操作返回类别、查询后的提议与实际执行记录。这为返回模型与继续查询策略提供过程观测，也能暴露“预计补齐，实际上只得到背景”“得到反对证据后仍走原路线”等可调查的问题。

来源语义与分支标签仍依赖同一 Agent 的提取，不是独立标注的真值。实际只看到了被选中查询的返回，未选候选没有反事实标签。当前同一比赛的少量续查也不是独立测试样本。后续要学习分支概率，仍需独立核验一部分提取、记录选择倾向与未覆盖状态、做时间分隔验证，并处理失败和时效变化。

沿用的前提投影还会将反向来源表述标为 `contested` 并保留缺口。这是保守操作规则，不是一般的信息缺失定义：可信的反向证据也可能已经回答问题。当前没有充分区分输入可得性、命题方向与来源冲突，后续价值模型不应把该缺口字段直接当作风险。旧版本轨迹保持其原语义。

真正的净信息价值还需要同一风险尺度上的终局决策模型与成本。例如 `R(E) - E_z[R(E, z)] - cost(a)` 中，既要有查询 `a` 的可信返回分布，也要有新证据如何更新可用决策风险的规则。七个操作标签不能直接替代这些量；预测误差百分比、HTTP 次数和货币也不能直接相减。现有历史或有限合成模型只在原来的状态、动作及假设范围内有效。

本协议的验收对象是前瞻计划、实际返回与后续行为的连接。价值驱动的候选排序和停止仍应以经过验证的观察模型、风险模型与成本依据来实现。
