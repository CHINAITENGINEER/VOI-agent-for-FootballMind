# 前瞻有限快照选择实验

`prospective-snapshot-choice-v1` 是 FootballMind 用来检验“Agent 是否会主动选择下一条最值得读取的信息”的实验协议。它把信息选择和正文理解分开：研究人员先登记一个固定问题与有限候选菜单，先把每个候选正文冻结到原始归档，再向 Agent 展示候选的来源角色、URL 和预算，但隐藏正文。Agent 只能选择一条、暂缓或停止；只有被选中的快照才会作为一次逻辑读取释放。所有快照在事后交给隔离评价器，用于逐路径重建来源报告。

这个设计回答的是一个比“模型是否预测正确”更窄、也更可审计的问题：在同一组可能的信息路径中，Agent 是否根据当前目标选择了更可能改变终态报告的路径。它不把预取 HTTP 算作 Agent 行为，也不把事后全菜单评价倒灌到 Agent 的输入。

## 固定协议

实验根目录包含以下不可变关系：

1. `manifest.json` 固定目标命题、损失语义、允许主机、候选 URL、来源角色和候选顺序。
2. `prefetch-ledger.json` 要求每个候选先登记再读取；每个快照绑定登记哈希、请求 ID 和原始归档。
3. `agent-input.json` 只含候选元信息和 `body_hidden=true`，不含正文、正文摘要或快照哈希可逆内容。
4. `agent-choice.json` 保存 Agent 的完整菜单审阅、候选理由、选择/暂缓动作和真实提供方回执。
5. `selected-release.json` 只释放被选候选的正文，并记录一次逻辑读取；暂缓时释放正文为空。
6. `evaluation-input.json` 只在 Agent 选择之后生成，向隔离评价器展示完整冻结菜单；评价器为每条路径返回 `direct_support`、`direct_challenge` 或 `no_direct_evidence` 等来源位置标签。
7. `evaluation-annotation.json` 由主机绑定目标哈希。评价器可以返回行级标注，目标对象始终由主机哈希固定。
8. `result.json` 分开保存选择路径投影、未选路径投影和全菜单联合投影；`selection_regret`、`expected_query_value` 和全局最优均在没有反事实效用时保持空值或 `false`。

## Agent 合同

Agent 面对的不是开放网络，而是有限的事前登记菜单。因此它可以说明：

- 某个来源角色可能回答哪个子问题；
- 该路径为什么与固定目标相关；
- 未选路径目前为什么优先级更低；
- 在只能读取一条时，先读哪条最有机会得到所需证据；
- 当前材料不足以排序时，选择 `stop` 或 `defer`。

它不得声称已经看到候选正文、编造正文中的事实、伪造 VoI 数值，或把“没有直接证据”当成反向证据。`query` 必须从已登记菜单中选出候选，且每一项候选都必须在菜单审阅中出现。

## 与信息价值研究的关系

该协议是信息价值（Value of Information, VoI）研究的**可观测前置实验**，不是 VoI 计算器。真正的期望信息价值需要候选路径的结果分布、获取成本、终态损失和反事实政策；本轮只有固定来源报告损失，没有校准的状态概率和实际货币成本，所以：

- 选择理由可以作为 Agent 的事前策略输出；
- 选中路径与未选路径的终态差异可以作为有限范围的结果描述；
- 一次选择尚不足以证明 Agent 已经估计出正确的 VoI；
- 未选路径没有改变终态，尚不足以证明全局停止最优；
- 来源报告本身不等于比赛世界真值或预测收益。

后续版本应把同一目标复制成多个冻结任务，随机化候选位置与来源角色，记录每条路径的真实读取成本，使用独立历史比赛结果计算决策损失，再拟合“选择概率—条件效用”的关系。当前版本先验证信息选择链是否真实存在、是否受到正文泄漏、候选覆盖和评价器篡改的影响。

## 失败和修复规则

提供方在 Agent 真正产生选择前拒绝 JSON Schema，属于实验前置故障，不应被计为 Agent 的 `stop` 或“不会选择”。修复 Schema 后，只允许在新的带 lineage 的实验根目录进行一次干净调用；旧失败目录保持原样。

评价器若返回与固定目标不同的哈希，属于评价输出绑定失败。新版本由主机计算目标哈希，并保留旧评价回执，允许一次独立的修复评价；修复评价只复用既有 Agent 选择和既有正文快照。

这两类失败必须进入最终分母和验收记录。否则系统会把“协议错误后重跑”误写成稳定的自主选择能力。

## 生产化接口

未来与足球数据平台接入时，候选项不再直接由研究人员手写 URL，而由检索器生成带版本的 `candidate_descriptor`：目标实体、比赛、时间窗、来源类型、预计成本、可用性和去重键。Agent 仍只看到描述和预算；读取工具负责把候选绑定到原始归档。模型层应消费 `source_position`、证据类型和新鲜度，而不是未经校验的自然语言摘要。

一个可上线的循环应记录：

```text
当前状态 S_t
    -> 候选生成 C_t
    -> Agent 选择 query(c) / defer / stop
    -> 工具读取并返回带证据的 O_t
    -> 状态更新 S_{t+1}
    -> 重新计算终态损失上界与剩余预算
```

停止标准在研究上应由“剩余路径的预期损失下降是否超过读取成本”决定，在工程上必须有预算、超时、重复路径、来源失效和证据冲突的硬上限。LLM 负责提出和解释候选，工具和验证器负责边界、计数、哈希及终态计算。
