# 停止后的独立未读路径评价

`football_agent.stopping_evaluation` 在 Agent 已经提出并通过准入的 `stop` 或 `defer` 后，登记一个有限的未读路径集合，独立读取并评估这些页面对原问题的影响。它不续写原 Agent 运行，也不改变工具选择或停止策略。

这一层解决一个可检验的问题：**Agent 停止后，指定未读路径的正文里是否发现了可改变来源报告的内容？** 它将“当前发现”与“停止时漏查”分别保留。现版本没有历史正文可得性认证，后者维持未知。

## 使用与数据流

Python 接口位于 [stopping_evaluation.py](../../football_agent/stopping_evaluation.py)：

1. `register(root, parent_root, run_id, paths)`：离线核验原运行，固定完整目标、原 claims、正文、停止时刻、原报告动作与评价路径。`paths` 每项包含 `path_id`、精确 `url`、研究人员选择理由。
2. `acquire(root, path_id)`：读取事前登记的单条路径，先保存意图和预算占用，再复用现有传输与 RawArchive。每条最多一次，最多三条；失败、中断和未执行分别保存。
3. `annotate(root)`：一次独立评价模型批次，输入只有固定目标和各路径当前返回。停止理由、原候选排序、原报告和选择理由不进入评价模型输入。
4. `verify_evaluation(root)`：只读核验、重建原文投影、核对模型输入输出并生成结果字典。调用方可用既有 `atomic_write` 保存报告。

每条路径必须在停止前交给 Agent 的文档链接中出现，而且原运行没有读取过相同执行动作。路径按 `read_url` 实际 endpoint 和参数去重，URL 参数顺序变化不会产生新路径。URL 已知只说明入口可发现，不证明当前正文版本在过去可得。

所有获取都在独立 root 中记录。原运行和原返回数据表不接收评价正文、评价 claims 或标签；若原运行字节发生改变，核验会报错。

## 评价口径

每个页面的评价是 `direct_support`、`direct_challenge`、`conflicting`、`no_direct_evidence` 或 `uncertain`。方向性结论需要适用原完整命题的声明原句及必要的比赛、原因语境，且引文必须命中取得的正文。失败或未取得正文只允许不确定，不转成反向结论。

程序逐路径计算：

`terminal_state(固定问题, 原claims + 本路径评价claims)`

每条路径都从相同原状态开始；另列全部路径的联合投影。如果两条新来源方向冲突，单路径可能分别支持/反对，联合结果仍可保留未知。这种动作变化仅是“接受这些来源标注后会得到什么报告”，不是正确率、因果收益或期望 VoI。

每条声明还核对其完整引文集合在旧正文中的可见性：

- 所有锚点原先可见：提示可能是提取遗漏或重复依据。
- 新旧锚点混合：保留新正文补足比赛/因果语境的可能。
- 全部为新锚点：仅说明文字依据新增，语义新颖性仍需复核。

新 URL、新文档 ID、正文长度或新 claim ID 都不单独代表新增信息。锚点重叠也没有被直接设为零价值。

## 时间、成本与覆盖范围

分母固定为全部登记路径数，获取失败、未执行、未完成标注均保留。获取覆盖与内容评价分别报告，不只统计成功页面。

本版本全部路径均为停止后的读取，`body_available_at_stop`、`missed_opportunity_at_stop` 和 `stop_regret` 不会被页面日期或零条发现自动填成确定值。页面自报早日期、旧列表已暴露 URL、后来成功读取，都不足以认证停止时这些字节已经可得。需要前瞻保存或可信版本证据后，再研究历史可得性的扩展。

评价 HTTP 和模型回合是独立研究成本；批量评价两个页面的模型成本不冒充 Agent 实际续查成本。预留后中断的请求保持待核对；已归档的物理请求可计数，总请求数有疑问时保持空值。

输入隔离减少评价模型受到原停止理由的影响，但同类语言模型、相同目标及人工选择集合不构成统计独立。文本评价有引文检查和独立复核，仍不是独立世界真值。现有版本不计算最优停止、无遗漏证书或预期净收益。
