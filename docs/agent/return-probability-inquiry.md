# 查询返回概率：前瞻预测与核对

`return-probability-inquiry-v1` 是 `information-choice-inquiry-v1` 的可选扩展。研究对象仍是 Agent 在当前证据下自主生成候选、选择信息路径并处理返回。本协议让“我预计会得到什么”成为查询前记录、查询后可核对的预测。

概率来自 LLM 主观赋值，没有经过训练或校准。目标是**当前工具及下一通有效提取所产生的操作标签**，并非足球胜率、事实可信度、状态条件 likelihood 或信息价值。调用依据保持 `llm_bounded_exploration`，程序不按评分高低选择工具。

## 配置与候选契约

在既有配置中将 `inquiry_protocol` 设为 `return-probability-inquiry-v1`；继续要求显式 continuation 预算准入，可复用 source_catalog 和已有正文。无需新的工具服务。

每个候选新增 `outcome_forecast`：

```json
{
  "status": "elicited",
  "probabilities": {
    "source_support": 0.10,
    "source_challenge": 0.05,
    "mixed_source_signals": 0.05,
    "context_only": 0.20,
    "discovery": 0.20,
    "no_answer": 0.10,
    "failure": 0.30
  },
  "basis_document_ids": [],
  "reason": "主观预期及其依据；本段示例不是生产先验。"
}
```

弃权时 `status=abstain`、`probabilities=null`，仍需说明理由。弃权不替换为均匀预测，也不记零分。引用 ID 必须属于当前已取得正文；目录提示可以作为判断背景，但不得伪装成已取得正文。数值必须有限、处于 [0,1]、七类齐全且求和误差不超过 1e-9；程序不自动归一化或裁剪概率。

七类及优先级沿用 `return-forecast-inquiry-v1`：NO_DATA 为 no_answer，其余非 OK 为 failure；有对应来源陈述时使用支持/反向/混合/背景类别；否则有新允许链接为 discovery，再否则 no_answer。含链接的背景仍可能是 context_only。类别不保证涵盖页面所有语义，漏提取仍可能发生。

## 顺序、评分与回放

1. 在同一公开状态中提出至多两条候选，提交各自概率、信息作用和比较理由。没有最少候选数要求。
2. 仅执行选择且通过准入的候选；分布与原查询意图一起写入 acquisition intent，在请求前冻结。
3. 下一通有效回复完成提取后，按现有分类规则产生首次标签，再核对冻结概率。继承文档不会新增本轮请求或评分。
4. 首次标签及分数保持不变；后续提取/复查只影响后续决策。同一路径后来被选中属于新状态，不倒填早先未选候选。
5. 回放逐事件维护已核验知识前缀。非 decision 事件不接受插入、修改或删除评分、上游标签、假设、要求、问题和陈述；decision 从已核验回复重新推导。仅重算哈希不足以伪造评分历史。

若后续模型回复被校验拒绝，已取得正文仍保存，但没有新的有效标签或评分。离线核验须从原回复重现相同错误，绑定紧邻的 rejected 事件及终止状态；拒绝的提议不进入知识状态或执行。此类轨迹使用 `VERIFIED_REJECTED_RESPONSE_TRACE_NOT_COMPLETED_INQUIRY`，与正常完成轨迹分开。导出可保留该次真实获取，query_review/return_review 为空；这不是阴性证据或零收益标签。

使用 raw multiclass Brier `Σ_k(p_k−1[k=y])²`，范围 [0,2]，以及自然对数 log loss `−ln(p_y)`。这是预测分布评分的口径，采用正确评分规则并不自动建立现实校准。[Gneiting 与 Raftery，2007，作者原文](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)

若命中事前零概率事件，JSON 保存 `log_loss_nats=null, log_loss_status=positive_infinity`；聚合中该项仍计入分母，并使整体 log loss 均值为正无穷。未执行、执行后尚无标签、弃权、零概率命中是四种不同情况。

均匀七类参考的 Brier 为 6/7、log loss 为 ln 7。它仅为固定弱参考：search_web 的 discovery 文档不能用于来源陈述，其前四类在当前协议下不可达；仅识别这一工具结构就可能优于七类均匀分布。该参考没有衡量上下文推理能力。

运行报告列出已获标签请求、评分及弃权。实验侧车报告还必须列出已冻结候选数、执行请求数、未选/未执行数、尚无标签数，绑定运行 head 及首次标签事件时间；避免仅报告已评分子集。

## 研究边界

返回边际分布 `P(Z|H,a)` 并不识别 VoI。以公平二元目标 Y 为例，工具 A 返回 Y，工具 B 返回与 Y 独立的公平二元变量。两个工具返回边际相同，在 0–1 决策损失下的信息收益却分别为 0.5 和 0。还需识别返回与目标状态的联合关系，以及返回如何改变终止决策和损失。

下一通同一 Agent 可见旧预测，也参与 support/context 等语义标签生成，可能产生自我确认或漏提取偏差。当前记录不是盲法标注或独立真值。评分只作为诊断，不反馈给工具选择优化器，不进行温度缩放等在此小样本上拟合的校准。

各请求在同一调查中自适应产生，共享网页和继承证据；请求数量不是独立样本数量。未选候选返回、动作选择概率、真实决策损失改善和完整信息交付成本仍可能未知。程序保持 `expected_gain=null`，不会把此分布接入现有数值 VoI 的状态条件返回模型。

后续研究应优先加入与预测隔离的语义复核，以及明确的终止决策和损失定义，再估计信息对这些决策的影响。评分提升本身不是本项目的研究终点。

第28轮真实执行还暴露了更靠前的瓶颈：联赛主体的赛季规则与球队主体的单场资格问题之间，缺少可表达且受证据约束的适用关系。旧协议要求两者 subject 完全一致，导致有原文锚点的规则提案被拒绝。下一版本应显式表示赛事、赛季、参赛球队和目标比赛之间的证据关系，并保持旧版本重放含义；不能简单删除主体限制。原始失败轨迹及被拒绝回复保持不变。
